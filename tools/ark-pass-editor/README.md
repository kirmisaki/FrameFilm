# Ark 通行证编辑器

独立本地静态网页，提供默认的竖版「干员档案」和横版「罗德岛学院学生证」。两种模板分别保存本地草稿；切换模板不会清空另一张卡的字段或头像。资料默认留空，不预设任何人物身份。

也可从 ForFilm 的通行证页面嵌入打开（`index.html?embedded=1`）。嵌入时复用 ForFilm 已连接的 Ark 和统一任务通道；连接、设备改名均在 ForFilm 页面完成，不会再次弹出蓝牙选择器。读取与发送可以取消；上传中断时 ForFilm 会断开连接并清理未完成的传输。返回连接页可重新连接。独立打开时仍使用本页的蓝牙连接和设备名称功能。

## 使用

在仓库根目录运行 `python -m http.server 8000 --bind 127.0.0.1 --directory tools`，用支持 Web Bluetooth 的浏览器打开 `http://localhost:8000/ark-pass-editor/`。填写资料后可下载 `profile.bin`、PNG 预览和可继续编辑的 `profile.json`。页面自动尝试存一份本地草稿；换浏览器或清理浏览器数据前请导出 JSON。蓝牙由用户点击「连接 Ark」后手动选择以 `FRAMEFILMARK` 开头的设备。连接后可点击「读取设备资料（替换当前草稿）」；页面会先确认，读取完整并校验成功后才覆盖草稿，因此请先导出需要留存的资料。

Ark 固件 3.2.5 起支持下方「设备名称」区域：连接后自动读取，亦可点击「读取名称」重试。用户编辑固定 `FRAMEFILMARK-` 前缀后的 1–16 个 UTF-8 字节，收到设备成功回包后提示已保存；重启设备使新广播名生效。默认后缀为完整 BLE MAC，自定义名称不做全局查重。旧固件无响应时仅提示升级，不影响通行证功能。

选择头像时按中心裁剪为 **128×160**，保持比例，再编码为 PNG data URL。导入/导出的 JSON 只包含这张缩图，不保存原始照片。头像可随时更换或移除。黑白头像与 App 一致使用 Film MonoFast（开启抖动为 Floyd-Steinberg，关闭时直接黑白量化）；灰度与彩色继续使用可选的 Film 抖动算法。代号、编号需填写或明确勾选「尚未设置」；所有文字按实际绘制宽度校验，签名最多三行。字段有误时不能导出位图或发送。

学生证有九款 PSD 原配色，默认「阿米娅」。切换配色只换底图，不改变头像、构图或字段。底图以原图层导出，保留标题、字段标签、色带、反白代号条、校印和水印，不包含实体外框、背面、竖排 `STUDENT`、印刷底边或示例头像和字段值。每款原稿 1011×638 按高度等比缩放至约 761×480，再居中裁去左右各约 20 个输出像素，直接覆盖 **720×480** 画布。头像窗和字段锚点沿用同一变换，不拉伸、不加留白。

将本地底图放在编辑器的 `student-palettes/fullscreen/` 下，以 JSON `palette` 的值命名（例如 `amiya.png`）：

| 配色 | JSON `palette` |
|---|---|
| 阿米娅（默认） | `amiya` |
| 狙击 | `sniper` |
| 医疗 | `medic` |
| 先锋 | `vanguard` |
| 近卫 | `guard` |
| 重装 | `defender` |
| 术师 | `caster` |
| 辅助 | `supporter` |
| 特种 | `specialist` |

网页编辑器使用此处的本地 PNG 路径，原始 PSD 和字体保存在本地。Flutter App 使用同一套底图，见 [学生证](../../app/flutter_app/README.md#学生证)。所选配色缺图、图片损坏或尺寸不符时，仍可切换配色、编辑和导入/导出 JSON；该配色不生成 PNG/BIN，也不会沿用上一款底图发送。补齐图片后刷新。

网页只叠加可编辑的头像、代号、学号和种族，不重画静态元素。右上原色带只露出 10 px，左侧渐变保持原样。学号按 `YYYYMMDD`（国服实装日期）加 `MMDD`（角色生日）填写，也可明确选择「尚未设置」。预览和 PNG 为正向 **720×480** 横版。默认采用 I006 连续色调和 A 档灰水印；灰水印只在保留的原稿浅灰水印区用白 75 与中性灰 407 扩散混色，满覆盖时目标灰态占比为 35%。可手动选择兼容 FFUI，按现有头像显示模式出黑白、灰度或 ColorFast 六色。发送后逆时针横拿 Ark 阅读。全屏卡面不显示状态栏和底部提示，确认键单击刷新、双击退出、长按休眠；其他页面方向和显示不变。

## 档案数据

`profile.json` 是 UTF-8 JSON。干员档案继续使用 v1：

```json
{
  "version": 1,
  "codename": "",
  "codenameUnset": false,
  "number": "",
  "numberUnset": false,
  "affiliation": "",
  "signature": "",
  "avatar": null
}
```

学生证使用独立的 v2 JSON：

```json
{
  "version": 2,
  "template": "rhodes-academy-student",
  "palette": "amiya",
  "studentOutput": "i006",
  "codename": "",
  "codenameUnset": false,
  "studentNumber": "",
  "studentNumberUnset": false,
  "race": "",
  "avatar": null,
  "avatarMode": "mono"
}
```

两版的 `avatar` 都是 `null` 或 **128×160 PNG 的 data URL**；`Unset` 字段为布尔值；`avatarMode` 为 `mono`、`grayscale` 或 `color`，旧 v1 没有该字段时按 `mono` 读取。学生证的 `palette` 和 `studentOutput` 随草稿、JSON 和设备回读保存。旧 v2 缺少字段时分别使用 `amiya` 与 `i006`；`studentOutput` 的另一选项为 `ffui`。未知值拒绝导入，不覆盖草稿。自动兼容发送不会修改这两项编辑偏好。导入会验证版本、类型、长度和头像尺寸。JSON 可保存未完成的草稿；设备发送需要通过布局校验。学生证首期只支持新版网页编辑，旧网页和 Flutter 不识别该 JSON；旧客户端仍可能直接发送旧档案来覆盖设备上的学生证。Ark 只保存一份活动资料，换模板发送前可先导出 JSON 和 BIN 作为备份。

## 主体图与设备文件

干员档案保持 **440×608** 主体图，状态栏和提示行仍由固件绘制。学生证 PNG 始终为 **720×480** 横向阅读方向。默认 I006 `profile.bin` 使用同一组色码封装为 **691,232 B** 的面板原生 **720×480** 单帧 ABC9；选择兼容 FFUI 时，文件仍为顺时针旋转的 **480×720** 位图。实体屏颜色可能与网页模型不同。

`profile.bin` 的 FFUI 版本独立于 JSON 版本。两种尺寸共用 16 B 头，宽高为 little-endian，其余保留字节为 0。黑白／灰度为 version=1、format=1（MSB first，1=黑、0=白），六色为 version=2、format=2（每字节两个索引，高半字节在左）。含头总大小：

| 位图 | 黑白／灰度 | 六色 |
|---|---:|---:|
| 干员档案 440×608 | 33,456 B | 133,776 B |
| 全屏学生证 480×720 | 43,216 B | 172,816 B |

发送前通过 `0x59` 查询通行证能力：I006 需要 bit11（图片 App 的 ABC9 bit5 不可替代）。未宣告 bit11 时，默认 I006 模式自动使用设备支持的全屏 FFUI：有 bit10 和 bit0 则用 ColorFast 六色，有 bit10 但无 bit0 则用黑白或灰度。手动选择兼容 FFUI 时按头像显示模式发送（彩色需 bit0）。没有相应全屏能力时不发送任何资料文件，旧设备上的资料不会被覆盖。离线下载按所选输出模式，不随连接状态改变。

蓝牙使用 ForFilm 的 `0x2000/0x2001` UUID 和 `0x55 CH LEN DATA SUM` 帧。每个文件按 START(0x03) → NAME(0x00，ASCII 路径含末尾 `\0`) → LEN(0x01，4 B 大端) → DATA(0x02，192 B 分片) → STOP(0x04) 发送；控制帧间 50 ms，数据帧间 4 ms（与现有 ForFilm 的 2+2 ms 相同）。现有 ForFilm 上传函数发送文件名时未显式附加 `\0`；Ark 固件接收端按 LEN 复制并补零，因此两种都能解析，此工具按项目字符串规范显式发送零结尾。先发送 `app/pass/profile.bin`，再发送 `app/pass/profile.json`。发送期间锁定资料编辑，确保文件对应点击发送时的画面。两个文件发送后通过 0x53 回读 profile.json 并与发送内容比对；一致才报告“回读一致”，否则明确提示回读未确认。取消或中断时断开连接，并保留已发送 bin / 未确认 JSON 的状态；重新连接后从头发送。设备协议没有文件保存 ACK，最终仍需在设备上按确认加载。

读取需要支持 **0x53** 的新版 Ark 固件。连接后同一 BLE characteristic 启用通知，一次只请求一块：请求 `offset`（uint32 BE）+ `count`（1..128）；响应为 `status`（1 B）+ `offset`（4 B）+ `total`（4 B）+ 数据（0..128 B）。`status` 依次为 0 成功、1 未配置、2 读取失败、3 忙、4 参数错误；忙时自动等待 500 ms 重试（最多 12 次）。页面验证帧头、通道、长度、校验和、offset 与 350000 B 上限，按 offset 拼齐 UTF-8 JSON，再校验 schema 与头像；全部成功后才替换表单和本地草稿。每块等待 7 秒，超时会提示可能需要新版固件。取消、断连、解析失败都保留当前编辑内容；读取和上传不能同时执行。
