FrameFilm / UI Layer / Design Draft 01

工业终端 · 1-bit 界面设计稿

视觉母题取自《明日方舟：终末地》的工业机能语言：三角形 UI 元素、几何化工业徽章、正交蓝图网格、 45° 切削角、粗犷区域标识、克制的黑白灰与大留白。本稿把它压到设备真实约束上 —— 纯黑白的 480×720 电子纸，没有灰阶、没有抗锯齿、没有色彩。

01 转译逻辑：色彩语言 → 1-bit 语言

终末地的界面之所以能在单色屏上仍然"像它"，是因为它的识别度并不建立在色彩上，而建立在 几何、线宽、标签密度与切削感上。唯一必须重新发明的是那抹"终末地黄"——它承担的是"强调 / 当前 / 激活"的职能。

终末地原语它的职能1-bit 转译
终末地黄强调、激活、当前项实心黑块 + 反白文字（最强的 1-bit 对比）；次强强调用 密度斜纹
三角形 UI 元素指向、层级、状态标记直接用 —— 实心/空心三角作为选择指针与列表符号
工业徽章 / Logo 变体身份认知（"你是管理员"）同心圆 + 贯穿十字 + 实心三角 + 底部缺口；作为开机画面与状态栏品牌标
CMYK 测试色带印刷工业感、加载态改为 密度递变的分段条（同一职能：一列"色阶"读数）
CAD 蓝图网格 / 坐标系工程感、精密感1px 正交细网格 + 坐标角标，仅在背景以极稀密度出现
45° 切削角、传送带剪影工业硬边clip-path 四角/单角切削；实心色块斜切
粗犷区域标识场地感、真实感大字号压缩体 + 实心底 + 编号（如 A-04 / SECTOR 7）
低饱和黑白灰 + 金属理性、可信、专业零转译成本 —— 本来就是这个调性
大留白呼吸、克制保留，且在电子纸上留白=白，零代价，还能减少残影
必须诚实的一条：斜纹与网点在固件里没有原生图案 API。实心块 / 线 / 圆 / 三角 可用 LVGL 图元直接画， 而 斜纹、网点、徽章这类复杂图形必须预渲染成 1-bit 位图（复用现有 cover.film 那条胶片管线即可）。 因此本稿的视觉主体刻意压在"实心 + 细线 + 文字"上，斜纹只作为强调备选。

05 可替换图标资源（SD 卡）

设备端的图标不写死在固件里 —— 放 SD 卡上按固定尺寸替换即可。 固件内置一份默认图标；SD 卡上存在同名文件且尺寸校验通过时，用 SD 版本覆盖。 本节只定义槽位与尺寸，不约束画什么。

图标SD 路径尺寸 (px)文件大小
菜单 app 图标 ×5 /sdcard/app/<app>/icon.bin
<app> = image / template / clock / animation / settings		 80 × 80 816 B
身份徽章（开机主视觉） /sdcard/app/_ui/badge.bin 304 × 272 10,352 B
格式：自有 FFUI 容器（小端），1bpp 载荷
0x00 magic "FFUI"　0x04 version =1　0x05 format =0x01　 0x06 width u16　0x08 height u16　0x0A reserve 6B　 0x10 载荷
· 位序：每字节 8 像素，MSB 在左　· 极性：1 = 黑、0 = 白
· 行字节数 = 宽 / 8（宽必须是 8 的倍数，这也是 80 与 304 的来由；徽章取 304 而非 300，是因为 300 不是 8 的倍数）
· 徽章纵向 272 由源图 icon1.png 的宽高比（641:573）定，改尺寸须同时改 gen_ui_assets.py 的 BADGE_W/H 与固件 ui_assets.h 的 UI_BADGE_W/H
· 文件总长 = 16（头）+ 宽 × 高 / 8
为什么不用 LVGL 官方 .bin / LVGLImage.py：官方 I1 路径要外部 pngquant 工具、 且 I1 图像依赖调色板方向；这里用 16 字节自有容器，固件侧把 1bpp 展开成 L8（亮度直接表达黑白， 没有调色板语义）再交给 LVGL，整条链路零外部依赖。
校验与回退：尺寸不符 / 文件缺失 / magic 或版本非法 → 回退到固件内置默认图，并打一条日志。 固件不做缩放，尺寸必须精确匹配（避免在 MCU 上做位图缩放与重采样）。
选中态反色是自动的：只需提供一份图标。当前选中项显示为"实心黑板 + 反白图标"， 反色由固件对展开后的亮度缓冲整体取反（~L8）得到，不需要画两套。
为什么只开放这几处：状态栏的电池 / WiFi / 蓝牙是 9~12px 的方块，用图元直接画更清晰、也更省 flash， 不值得做成资源；而菜单的 5 个图标与整机徽章是"唯一看得出作者风格"的位置，所以开放替换。
硬约束：设备端不支持中文。固件字体只有 Montserrat（拉丁）与 UNSCII 8（终端等宽）， 没有 CJK 字形，所有设备端文案必须是 ASCII。这也是本稿把 app 名、设置项、描述全部写成英文的原因。 若将来需要中文，要额外引入子集字体（占 flash），属于单独议题。
生成方式：python tools/ui-assets/gen_ui_assets.py（只用 Pillow，零外部工具） 一次产出两样东西，两者同一套画法，所以"默认样子"与"替换后样子"一致：
① SD 卡可替换资源 assets/app/<app>/icon.bin、assets/app/_ui/badge.bin（拷进 TF 卡即生效）
② 固件内置默认图 components/film_ui/{inc/ui_defaults.h,src/ui_defaults.c}

两个实现约束与落地方式：
① SETTINGS 写参数不能直接在 ui_task 里调 service_param_save() —— 该模块声明"无内部锁，依赖只在 app 任务串联调用"。已按此约束实现：页面只上报 [行号, 候选下标]（app_manager_post_ui_msg），由 app 任务侧校验、写参数、落盘， 再把设备侧真实值组成的整页快照回投给页面（ui_core_post）。
② BOOT 画面的时间成本：首帧 mono 本来就必须做一次完整清场（实测约 3 秒）。 把 BOOT 画面作为首个 mono 帧画出，这次清场就是"免费"的 —— 已按此实现。 开机行为现由 BOOT PAGE / START APP 两个 app 层参数决定（设置页可改，默认 SHOW + MENU）： 默认仍走 BOOT（约 18s 自检步进，其中首帧清场约 3s）→ 主菜单，之后双击 ENTER 回主菜单、长按 ENTER 休眠； 想省掉这次清场可直接 SKIP 开机页落到指定 app（代价是不再清场，残留会留在屏上）。

刷新策略（这一页最大的设计约束）

电子纸每次上屏都是"全帧"，代价与改动面积无关。实测一次 1-bit 单色全屏刷新约 940ms， 期间画面会闪一下。所以这一页的设计目标不是"表达力最大化"，而是 在不牺牲读数感的前提下把刷新次数压到最低：
做法理由
lv_timer 1 秒一拍，只在"分钟"或"日"变化时才 set_textLVGL 只在 dirty 时渲染 → 实际约每分钟一帧，而不是每秒一帧
分钟尺取 2 分钟一格（30 格）尺子每 2 分钟才动一次；取 1 分钟一格（60 格）则格宽只剩约 6px、且每分钟都动
不做秒针 / 秒级读数1 秒一帧 = 86,400 帧/天，面板闪烁与功耗都不可接受
代价要诚实说：即便如此，仍是 ≈1,440 帧/天。作为桌面钟长期通电使用时， "每分钟闪一下"很可能不能接受。建议在 SETTINGS 里增一档"时钟刷新间隔"（1 / 5 / 15 分钟）， 让用户自己把闪烁换到可接受的程度 —— 这是本次设计新提出的一项待办，尚未实现。

08 休眠卡设计（SLEEP · 本次新设计）

从主菜单长按 ENTER 进入休眠。设备在睡着之前先把屏幕换成这张卡， 然后进 deep sleep —— 电子纸断电保像，所以这张卡就是设备整个休眠期间的"封面"， 会一直挂在冰箱上看。它的设计目标因此不是"信息量"，而是三件事：确认它真的睡了、 告诉人怎么叫醒它、保持安静的姿态。

交互时序

#步骤要点
1主菜单长按 ENTER（约 0.8s）长按已是全局的"手动休眠"语义（各 app 内长按同样睡，只是不画这张卡）；双击才是"退回主菜单"
2调度器切到休眠页，页面绘制这张卡一次全帧刷新（~940ms），画面在按下期间就已换成卡
3等按键松开关键坑：唤醒源是 ENTER 所在 GPIO 的电平触发（ext0，STD/PRO 低有效、MAX 高有效）。若在"长按还按着"时就 esp_deep_sleep_start()，唤醒条件当场就满足，设备会立刻醒回来 —— 表现为"长按后闪一下就恢复"
4按参数配好定时唤醒，进 deep sleep沿用 monitor_enter_low_power() 的顺序：先 hal_pwr_wakeup_prepare() 配好唤醒源（ext0 失败则本次不睡、保持 pending 等心跳重试）→ 停心跳 → 逐个 deinit（BLE / LED / 电池 / SD / EPD / 输入）→ hal_pwr_enter_sleep()；sleep_auto && sleep_time > 0 时才 hal_pwr_set_timer_wakeup()
5唤醒 = 复位重启 → BOOT → MENUdeep sleep 本质是复位，所以休眠页不会"退回去"，也没有返回路径

#问题决定
1手动长按休眠要不要受"休眠模式开关"（BLE 0x25）约束不受。该开关管的是自动休眠；用户明确按下的动作就该执行。定时唤醒仍按既有条件跟随参数（sleep_auto && sleep_time > 0），与自动休眠路径同一判据。

3状态字STANDBY
4唤醒后是否跳过 BOOT不跳过，完整走 BOOT（约 18s 进度条）→ 主菜单

Appapp_sleep.{h,c}（新建）休眠卡页面 + app_sleep_set_info() + app_sleep_run()（出示卡片 → 等 4s 地板 + 唤醒条件解除 → 请求低功耗）。
Appapp_manager.{h,c}新增 app_manager_sleep_show() 与 m_sleep_page 占屏门闸；主菜单 INPUT_PRESS_LONG → app_sleep_run()。
流程就是：长按事件 → 画休眠卡 → 断电。代码也是这个形状，"可以断电了"要同时满足两件事，缺一不可：
① 距切页已过 4s（SP_DRAW_WAIT_MS）—— ui_core_page_enter() 是异步的，没有回调能告诉你"第一帧已上屏"，只能按时间兜。 这个值别按"单帧 940ms"去推：上机实测 2s 不够（卡还没刷出来就断电，屏幕停在旧画面/半张卡），换页后第一次上屏明显慢于稳态单帧； 而 EPD 挂在外设供电轨上，断电即停在半途。
② 唤醒条件已解除（hal_pwr_wake_condition_met() 为 false）—— ext0 是电平触发，而长按是按住期间上报的，那一刻唤醒脚必然还满足条件，按着断电会当场醒回来。 这条只会让入睡更晚、不会更早，所以是与 ① 叠加而非二选一。
一直按着不放时 15s 兜底（打告警后照睡）。
