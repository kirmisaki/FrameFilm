# Ark 硬件与固件更新

连接 Ark 后，在连接页的 **连接信息** 中查看主控、硬件配置、Flash 和 PSRAM。它们与 SD 卡状态位于同一张卡片中。当前两套配置都属于 ESP32-S3 系列，固件仍需区分内存规格：

| 配置 | 主控 | Flash | PSRAM | 在线固件附件 |
|---|---|---|---|---|
| N4R2 | ESP32-S3 | 4 MB | 2 MB · Quad | frame_film_ark-n4r2.bin |
| N16R8 | ESP32-S3 | 16 MB | 8 MB · Octal | frame_film_ark-n16r8.bin |

在设置页检查固件更新时，App 会按当前连接设备的硬件配置选择兼容附件。硬件发布清单 `framefilm-ark-firmware.json` 与镜像内目标相互核对；本地导入固件也按同样的硬件要求检查。每次发送或重试前会重新读取设备信息，切换设备后不会沿用旧型号。

设备显示版本 **3.2.6** 保留为既定版本文字，更新使用实际 ELF 构建指纹判断。广播名称和屏幕尺寸也不用于推断硬件配置。

## 旧固件首次升级

以下 App 流程适用于设置页已有 **N4R2 / N16R8** 手动选型入口的客户端；没有该入口时，请使用下方 ForFilm 网页备选。

如果连接信息显示尚未识别硬件，设备可能仍运行不支持硬件身份查询的旧固件。图片等其他功能可以继续使用。App 提供首次升级的手动选型入口，默认不选择型号：

1. **先确认实物配置。** 根据主控模块标识、购买记录或板卡提供方确认是 N4R2 还是 N16R8。不确定时先核实，不要根据设备名称、屏幕或版本猜测。
2. 在 App 连接设备后进入 **设置 → 固件升级**，按实物选择 **N4R2 / N16R8**。这只是本次连接的手动目标，不代表 App 已验证硬件。
3. 点击 **检查 GitHub 发布 → 下载并校验**。App 按手动目标选取附件，校对发布清单、文件 SHA-256、ELF 构建指纹和镜像内的目标描述。也可通过 **选择固件** 导入同型号的原始应用 `.bin`。
4. 点击 **检查并升级**，阅读首次升级确认框，确认实物 Flash / PSRAM 配置与目标一致后开始。旧固件不能自动验证硬件，选错配置可能无法启动，需要 USB 重新烧录恢复。取消不会开始升级；重试时需再次确认。
5. 保持设备供电和连接，等待设备重启及构建指纹核验。重新连接后在连接页确认 **N4R2 / N16R8、Flash 和 PSRAM** 与实物一致。显示版本为 **3.2.6** 属于正常现象。

手动选择和在线候选在断连或更换连接后清除，不会替另一台设备保留型号。每次启动或重试仍重新查询设备能力与硬件身份；只有未声明硬件身份能力的旧固件可使用本次明确确认的目标，并按设备实际 OTA 槽容量检查。已识别设备按自动读取的型号升级，不能手动改成其他配置；设备已声明硬件身份能力但查询失败时，也不能用手动选型绕过。

### ForFilm 网页备选

也可以使用 ForFilm 网页的蓝牙 OTA 完成首次安装：

1. **先确认实物配置。** 根据主控模块标识、购买记录或板卡提供方确认是 N4R2 还是 N16R8。不知道配置时先向提供方核实，不要根据设备名称、720×480 屏幕或显示版本 3.2.6 猜测，也不要默认选 N4R2。
2. 打开 [Ark Release](https://github.com/kirmisaki/FrameFilm/releases)，选择包含硬件发布清单 `framefilm-ark-firmware.json` 的正式版。在该版本的附件中，按上表下载明确命名的 **`frame_film_ark-n4r2.bin` 或 `frame_film_ark-n16r8.bin`**。这是原始 OTA 应用镜像；不要选择带 `flash` 名称的合并镜像、bootloader 或分区表。
3. 退出 App 的设备连接，让网页独占蓝牙连接。使用支持 Web Bluetooth 的 Chrome / Edge 打开 [ForFilm Web 工具](https://kirmisaki.github.io/FrameFilm/tools/ForFilm/)，点击 **蓝牙扫描**，在浏览器设备列表中选择自己的 Ark。在线页面不可用时，可按 [ForFilm 本地使用说明](../../tools/ForFilm/README.md#本地使用)启动本地网页。
4. 进入底部 **设置**，找到 **设备控制 → 固件升级**，点击 **选择文件**，选择第 2 步的对应型号 `.bin`，再点击 **开始升级**。保持设备供电与浏览器连接，等待发送结束及设备重启。这里使用蓝牙 OTA，不需要点击“USB 连接”或“串口烧录 · 完整固件”。
5. 网页显示 **100% / 已发送，待设备重启与版本核验** 只表示发送阶段结束。等设备重新启动后，断开网页蓝牙，在新版 App 中重新连接并刷新设备信息；确认连接页出现与实物一致的 **N4R2 / N16R8、Flash 和 PSRAM**，再在设置页检查在线固件更新。显示版本为 **3.2.6** 是正常现象，后续更新按实际构建指纹判断。

ForFilm 的这条蓝牙 OTA 流程不要求旧固件先支持硬件身份查询，因此可用于首次安装；网页只检查原始 ESP32-S3 应用镜像和不超过 1900 KiB 的大小，不会替用户确认 N4R2 / N16R8，选包必须先完成实物核实。

如果网页在初始化、发送或结束阶段提示中断，先检查设备是否已重启、能否重新连接，不要把断连或 100% 当成安装成功，也不要反复盲目重发。若新版 App 仍无法识别硬件，核对下载的发布版本和文件名；容量或分区不匹配时，应依据该设备现有分区配置另行处理。

OTA 只更新应用分区，不修改分区表。设备还会检查当前 OTA 槽是否容纳目标镜像；更换内存配置的应用固件不会自动扩展已有 OTA 分区。

固件在激活新镜像前再次核对实际硬件与镜像目标，不匹配时保留当前运行镜像。协议与镜像字段见 [BLE 协议](../blecmd/blecmd_protocol.md)。
