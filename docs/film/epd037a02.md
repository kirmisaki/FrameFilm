# EPD037A02 同屏刷新与校色

目标为实物排线 **HINK-T037A02-A1 / EPD037A02**、驱动IC **JD7601**。原生720×480，观看480×720竖屏、排线下、标记左上。GDEH037E01是佳显料号，只作交叉参考，不直接混用校色参数。

## 已有依据

[OSPTEK原厂资料](https://github.com/osptek/display-epd-3.7inch-480x720/tree/main/versions/EPD037A02)给出六色、32pin、JD7601与2MHz示例；示例时钟不是最大频率证明。PDF有TBD及BUSY说明矛盾，需结合源码和本机日志。[佳显资料](https://www.good-display.com/product/991.html)机械图与函数的IC命名不一致，关闭的water-ripple分支不证明47fps。

用户提供的[同型号项目](https://oshwhub.com/sila/project_mspomzec)截图描述64码及512/4096码扩展，尚未取得附件源码；不据此承诺有效色数。本地仅保留epd-color-lab的5个核心文件，并非完整clone；其中波形文件注明源自FrameFilm，9份数组与当前Ark相同，不能作为独立的字段说明。

## 本轮工具

[串口诊断](../../tools/epd-profile/README.md)由默认关闭的 CONFIG_ARK_EPD_PROFILE 启用，记录MonoFast/ColorFast/ColorQual的INIT、LUT、RAM、REF、PON、POF及总耗时。SPI错误、BUSY超时或忽略BUSY的调用不计成功。

[同屏测试生成器](../../tools/epd-panel-lab/README.md)输出两种彩色各两页32码色卡、12帧Mono基准、PNG和manifest。全部0..63直接入文件，不经RGB重新量化；预览只是当前Web RGB估计。本轮不修改LUT、PLL、电压、40MHz SPI或刷新延时，不新增编码格式。显示版本保持3.2.5。

## 实测顺序

1. 记录ELF指纹、排线型号、温度、此前画面和文件列表。用独立文件名，不覆盖用户图片。
2. 通过现有网页上传，核对回包及文件列表。单帧归film，多帧归animation；先确认方向、完整显示和无错位。
3. 播放Mono基准，分开记录首次准备帧、同一保持上电会话的稳态帧。停止后的POF不归上一帧；不把预热结果当冷启动，也不把重复画面与黑白翻转当相同负载。
4. 固定顺序显示Qual/Fast色卡，等待完成并记前一画面和模式。取样避开字、边框和X。照片只能定性对比；准确RGB/Lab校色需受控照明和测量设备。
5. 用 python tools/epd-profile/summarize.py capture.log --json 汇总。空日志、截断记录和失败样本保持失败/缺失，不填0冒充实测。

## 判定边界

Mono源图43200B展开成172800B全屏传输。40MHz线速至少34.56ms，47fps预算21.28ms，当前路径不满足47次完整更新/秒。这是传输下界，不是实测帧率；RAM含编码/SPI事务/BUSY，REF含命令/BUSY/固定延时。历史410ms/帧和3.35s首帧只作历史记录。

分段结果再决定是否优化批量SPI、同LUT免重载或调度。未知轻量传输、窗口命令、PLL映射须有同控制器依据再验证。分别记录编码数、候选数、不同RGB数、实屏可分辨色数，不以512/4096编码代替有效色测试。通行证继续ColorFast快刷，Film保留ColorQual和已有实测色板。

## 2026-10-26 参数修复与25fps目标分析

用户将目标限定为：允许降低《Bad Apple!!》视频分辨率，但要求实体画面至少25fps。25fps预算40ms，不能以文件的帧率标记、完成回包或函数调用数代替可辨别的有效显示帧率。用户视频短链 https://b23.tv/RYeFfWu 本次访问返回HTTP412，未下载或转换视频；以下不假定该资源的实际分辨率、时长和编码。

### 先修复冷启动参数查询

BLE GET路由原先直接调用owner->on_param_get，未载入的动画RAM状态会返回frame_ms=0。现在统一走已有app_manager_param_get，按原NVS槽载入或套默认值后再回包。0x46/0x48/0x4A共用该路径；SET、参数结构、state_ver、NVS布局和已保存值均不变。检查脚本 tools/epd-profile/check_app_param_get.py 编译实际C路由及load/save函数，验证冷/重复GET、无保存/进入app、冷/重复SET和默认值回落；NVS/BLE/参数回调是接口fixture，不等于硬件验证。

### 当前三个独立限制

1. 当前Mono是全屏差分：1bpp输入43200B，但每次向DTM1写172800B。未变化像素使用差分码，不等于硬件窗口传输。原注释的“JD7601无窗口命令”没有公开寄存器手册支撑；准确边界应是当前路径未实现窗口，尚未取得本屏可用窗口命令依据。
2. 当前同屏BUSY低宽约121.2ms。即使软件编码和传输耗时全消失，沿用此单周期也不能达到40ms；保持全屏串行写入和同波形时，线速34.56ms+BUSY121.2ms的理想下界约155.76ms，即约6.42次/秒，尚未计入恢复等待、事务和其它开销。这是条件计算，不是已达到的帧率，也不是本屏换模式后的绝对上限。
3. 动画参数最小100ms，当前app用100ms tick累计并由FRAME_DONE接续；即使将来面板快过40ms，也需另行改为准确的帧期限调度，并同步参数范围及设置候选。单独把数值改为40不能解决前两项，本轮未提前扩展这些接口。

### 已核对与尚未知

直接从当前 hal_epd_370.c 提取9份799字节数组，实际8份互异；mono_fast与mono_clear有31个不同字节。偏移采用从0开始：

`10, 96, 98, 99, 184, 185, 186, 187, 190, 193, 272, 273, 274, 275, 278, 281, 360, 362, 363, 448, 450, 451, 536, 538, 539, 624, 626, 627, 712, 714, 715`。

## 2026-10-29 A/B/C 独立相位诊断与首轮实测

本轮先查开源来源，再准备本地候选。[OSPTEK 当前 canonical 仓库](https://github.com/osptek/display-epd-3.7inch-480x720/tree/694caf755bac88428058eddda4730fffce5ed26e) 的 ESP-IDF 示例 `examples/esp32s3-jd7601-spi-bringup/main/screen_driver/screen_driver.c` 与 `versions/EPD037A02/code/3D7_E6_480x720_7601(2).c` 提供标准六色 DTM1→REF 路径；该仓库代码许可为 CC BY 4.0。旧官方链接已同步 canonical，前述历史结论仍保留。OSHWHub 同屏项目本次可见附件区为“暂无数据”，没有取得可直接复用的 512 色扩展源码。这里的结论限于本次实际可访问来源，不能推断不存在其他实现。

本实验不移植原厂 C，也不修改现有九份 LUT。独立 `CONFIG_ARK_EPD_ABC_DIAG` 默认关闭，仅作用于 ColorQual。实验固件从 Format2 的 native 帧主体首字节读取 `(mode << 3) | B`（都在合法 0..63 内）；mode 0 复用第二相 RAM，mode 1 在第二相前重写 A，mode 2 在第二相前写常量 B。mode >2 在 spectra 初始化及新增清屏/Qual 刷新前拒绝（上层已有显示初始化仍会执行）。ColorFast 与其他正常路径保持现有行为；这不是公开协议或正式 film 格式扩展。普通 Format2 图片可能恰好匹配合法标记，实验固件只用于明确列出的诊断文件，完成后恢复正常固件。

各次都先执行同一个 `full_clear`，再使用原有 `qual_phase1/2/3` 和 PON/POF、BUSY 逻辑，合计 1 次 clear REF + 3 次 Qual REF。mode 1/2 多写 172800 字节 RAM，增加传输和等待时隙，不能称“完整时序不变”。mode 1 是额外 RAM 写入的控制组；新增常量函数只写 DTM1，不调用带 REF 的 `epd_spectra_fill()`。清屏操作一致也不代表已测得完全相同的光学初态。

`tools/epd-panel-lab/abc_diag.py` 默认生成四个单帧 Format2：原序列、rewrite A、B0、B7；每页相同位置保留全部 64 个 A/C 原始码块和原有 X 标记，页头写 mode/B。标记位于 file offset 32、native body[0]，对应 portrait (0,719)，不是左上方向圆点。采样避开该像素、文字、边框和 X。PNG 仍使用原 ColorQual A/C RGB 估计，仅帮助定位；不能预测独立 B 响应，不生成虚构 512 RGB 色板，不覆盖任何 profile。`--all-b` 可额外生成完整八种 B 页及两个控制组，只生成、不自动上传。512 个驱动组合候选不等于 512 个稳定、可分辨颜色。

相机UI明确提示自动曝光/自动对焦已锁定，但JPEG EXIF仍显示曝光1/25～约1/17秒、ISO1000～1250发生变化，白平衡为自动；因此不能宣称各张曝光完全相同。原始JPEG、仅做透视整理的并排图，以及512行逐码取样CSV保留在本地忽略目录 `.output/ark/abc-mid-20261029/`。CSV明确为未校准的相机RGB，不是屏幕sRGB/反射色度或正式palette。两张B=5的64格RGB逐通道平均绝对差约1.98/255，原序列前后约3.65/255；这些只作照片差异诊断，不是DeltaE、光学重复性阈值或有效色数。

结论：第二相数据有可控的实屏作用，中间B值可作为继续筛选颜色的候选；但固定B时许多不同A/C组合外观近似或失去对比，**本轮仍未证明512个稳定、可分辨的有效颜色**。现有三相也不是独立、线性的RGB三个通道。后续应先在固定光源、可核实的固定拍摄参数/色度标定下筛选有价值的三元组，比较其相对现有ColorQual色板的增益，再确定有效色数。此轮不把相机RGB写入正式色板、不新增9bit文件格式或App“512色”选项，通行证ColorFast路径不变。

本轮结束再次恢复归档正常BIN，0x56实读完整ELF为 `b7120217633972e13facafba93bf7140f12ed214b4826fce590516be1126d41c`、版本3.2.5。App重连后按名显示 `N2A900A1.film`，日志核对172832字节加载、显示完成和power off；相机确认白底、色块与方向恢复，照片左下存在局部反光，仅作恢复观察，不作色差或细纹测量。已退出相机并恢复本轮临时保持亮屏设置。个人档案、正常固件配置、App上传/UI与正式色板未改，未推送或发布。

## 2026-10-29 第三轮：固定参数录像取样与整张 ABC 图片
