# FrameFilm AI 信息屏设计文档

> 状态：v0.1 设计草案（先定形态与功能，再进入实现）
> 硬件基线：FrameFilmCommon 通用主板 + GDEM075T41WT 7.5" 800×480 黑白电子纸
> 固件基线：`firmware/frame_film_info/`（单机型信息屏基础工程）

---

## 1. 产品定位与形态

### 1.1 一句话定义

一台**放在桌面或墙上的 AI 信息屏**：把手机里分散的天气、日程、待办、新闻、照片和 AI 摘要，整理成一屏每天都会看的「信息卡片」，用电子纸常驻显示，只有真正变化的内容才刷新。

### 1.2 形态

| 项 | 设计 |
|---|---|
| 尺寸 | 7.5" 横屏，800×480，黑白 1bpp（124 DPI） |
| 摆放 | 桌面支架 / 墙面挂装 / 冰箱磁吸（共用外壳思路） |
| 供电 | 单节锂电池 + USB-C 充电；桌面模式可长期插线 |
| 交互 | 机身 1 个按键 + 手机 App / 网页 |
| 常驻 | 断网、断电前画面保持；深睡后按键唤醒 |
| 定位 | 不是「小电视」，而是「每天扫一眼」的低打扰信息终端 |

### 1.3 与冰箱贴的差异

| | FrameFilm 冰箱贴 | AI 信息屏 |
|---|---|---|
| 核心内容 | 照片 / 动图 / 通行证 | 结构化信息卡片 + AI 摘要 |
| 刷新 | 换图时整屏刷新 | 局部/差分刷新为主，整屏刷新兜底 |
| 交互 | 三键或编码器 | 单键 + App，默认不打扰 |
| 在线 | 主要靠手机蓝牙传图 | WiFi 定时拉取 + BLE 配网/控制 |
| 屏幕 | 多色 4bpp | 单色 1bpp，强调排版与灰度抖动 |

## 2. 目标用户与场景

### 2.1 目标用户

- 想在桌面/玄关/厨房获得「一眼信息」的人
- 不喜欢手机通知打扰，但需要日程、天气、待办提醒的人
- 电子纸/低功耗设备爱好者
- 需要给家人（老人、孩子）展示固定信息的人

### 2.2 高频场景

1. **早晨**：起床后自动更新为「今日简报」——天气、日程、待办、一句 AI 摘要。
2. **白天**：时间、天气、下一件事常驻；变化时只刷新局部区域。
3. **工作**：专注模式，只显示当前任务与倒计时。
4. **回家**：切换为家庭信息板——留言、购物清单、家庭日程。
5. **夜间**：低亮度/休眠卡，定时唤醒更新，不发光打扰。

## 3. 硬件基线（FrameFilmCommon）

| 项 | 规格 | 对设计的约束 |
|---|---|---|
| 主控 | ESP32-S3-WROOM-1-N16R8（16MB Flash / 8MB Octal PSRAM） | 可缓存多天内容与字库；不能本地跑大模型 |
| 屏幕 | GDEM075T41WT，800×480，黑白 1bpp，UC8179 | 全刷有闪白；支持差分/窗口局部刷新 |
| 屏幕电源 | 3V3_C 由 GPIO9 控制 | 深睡前必须刷完并断电；局部刷新期间不能断电 |
| 输入 | 单按键 GPIO4（低有效，EXT0 唤醒） | 交互必须极简：单击/双击/长按 |
| LED | WS2812 GPIO5 ×1 | 配网/低电/连接状态提示 |
| 电池 | ADC GPIO6 + 采样使能 GPIO7 | 低电策略、电量卡片 |
| 存储 | TF 卡 4-bit，无检测脚 | 内容缓存；插拔只能靠挂载结果判断 |
| 音频 | U6 7 路 GPIO（AUDIO1~7） | 预留语音/提示音；当前固件未驱动 |
| USB | CH343P 串口 + 原生 USB（GPIO19/20） | 烧录/调试；原生 USB 可做数据通道 |
| 面板 ID | `0x09`（BLE `0x42` 回包） | 客户端需按 800×480 单色出图 |

> 详细电源树与引脚见 `hardware/model/FrameFilmCommon/README.md` 与 `pinmap.csv`。

## 4. 核心体验原则

### 4.1 架构决策：纯 SSR 薄客户端（v0）

**决定**：v0 不引入 LVGL，也不在设备端做 UI 排版。所有页面由服务端渲染成 1bpp 整帧或区域位图，设备只负责联网拉取、缓存、校验和上屏。

**理由**：

- 设备本来就要定时深睡；睡眠期间屏上时间不会走，本地合成层换不来「分钟级时钟」。
- 信息屏的主要变化来自云端内容（AI 摘要、日程、新闻、照片），设备端排版只会增加固件复杂度。
- ESP32 的功耗模型决定了「醒来 → 联网 → 上屏 → 深睡」的批处理方式更合适；常电模式则可以直接提高拉取频率或保持长连接。
- 局部刷新仍然保留：用于常电模式、同一次唤醒内的多区域更新，以及服务端下发的区域增量；但它不是本地 UI 渲染。

**边界**：设备端保留必要能力：WiFi、HTTP(S)、FFSP 解析与校验、PSRAM 下载缓冲、EPD 全刷/差分/窗口刷新、按键请求下一页、NVS 记录版本、低电/断网兜底。**SD 仍初始化，作为离线页/动画帧/日志/素材的可选缓存，SSR 主链路不依赖它；不使用 `.film`，不做本地文字排版。**

### 4.2 核心体验原则

1. **一眼可读**：3 秒内看懂最重要的 3 件事，不要求用户学习界面。
2. **低打扰**：不做手机式通知流；AI 负责「替你筛选」，不是「给你更多」。
3. **服务端排版**：所有版式、字体、换行、图标由服务端渲染，设备只贴图。
4. **缓存可用**：电子纸本身保持最后一帧；SD 可选缓存最近页面/动画帧；NVS 只记录 `page/version`，断网/服务器故障不改变当前画面。
5. **按键可达**：切页优先读本地缓存，不依赖当场联网；长按才触发强制同步。

## 5. 信息架构与页面形态

### 5.1 首页仪表盘（默认）

800×480 横屏，建议 12 列栅格、24px 基础边距：

```
┌──────────────────────────────────────────────────────────┐
│ 09:41   周三 11/27        ☀ 12°~20°       WiFi  ▮▮▮▯  │  ← 状态栏（局部刷新）
├───────────────────────────────┬──────────────────────────┤
│                               │  今日日程                 │
│   AI 今日简报                 │  09:30 周会              │
│   · 上午有雨，带伞            │  14:00 评审              │
│   · 14:00 设计评审            │  18:30 健身              │
│   · 3 件待办待处理            │                          │
│                               ├──────────────────────────┤
│                               │  待办 3/7                │
│                               │  □ 提交周报              │
│                               │  □ 回复邮件              │
├───────────────────────────────┴──────────────────────────┤
│ 下一班公交 08:12 · 倒计时 2 天 · 今日步数 6,240          │  ← 底部信息条
└──────────────────────────────────────────────────────────┘
```

- 左 2/3：主卡片（AI 简报 / 照片 / 专注任务，可切换）
- 右 1/3：上下两个小卡片（日程、待办）
- 顶部状态栏：时间、日期、天气、网络、电量
- 底部信息条：一条轮换的次要信息

> 以上版式、文字、图标全部由服务端渲染成 1bpp 位图；设备端只负责贴图和按 FFSP 区域表刷新，不做本地排版。

### 5.2 卡片类型

“刷新方式”指 FFSP 区域表中声明的刷新策略，不是设备端渲染策略。

| 卡片 | 内容 | 刷新方式 | MVP |
|---|---|---|---|
| AI 今日简报 | 3~5 条个性化摘要 | 整屏/卡片区 | ✅ |
| 天气 | 当前温度、最高最低、降水、空气质量 | 局部 | ✅ |
| 日程 | 今日/明日日程，临近高亮 | 局部 | ✅ |
| 待办 | 清单，完成状态 | 局部 | ✅ |
| 照片 | 家庭照片/每日一图 | 整屏 | ✅ |
| 时钟/倒计时 | 大号时间、纪念日、考试倒计时 | 局部（随唤醒周期） | ✅ |
| 新闻/资讯 | AI 筛选的 3 条标题 | 整屏/卡片区 | P1 |
| 习惯打卡 | 喝水、运动、吃药 | 局部 | P1 |
| 二维码 | 支付/名片/WiFi/网址 | 整屏 | P1 |
| 语音问答结果 | 手机语音转文字 → AI 回答 | 整屏 | P2 |
| 家庭留言板 | 多人留言、手写体 | 局部 | P2 |

### 5.3 专注模式

- 只显示：当前任务、剩余时间、结束时间、一句鼓励。
- 常电模式可由服务端按分钟/秒级下发局部区域；电池模式跟随唤醒周期更新。
- 长按退出，回到首页。

### 5.4 设置与配网

- 首次使用：BLE 配网（WiFi SSID/密码）+ 绑定账号。
- 设置项：卡片顺序、内容源、刷新时段、夜间休眠、电量提醒、时区。
- 设备端只保留最小设置（翻页顺序、亮度/对比、休眠时间），复杂配置放 App。

### 5.5 睡眠画面

- 夜间或手动休眠：显示极简睡眠卡（日期、月亮图标、下一唤醒时间）。
- 深睡后按键唤醒，先恢复上一帧，再按需差分更新。

## 6. AI 能力设计

### 6.1 内容生成（云端）

设备不跑大模型，AI 在云端/手机侧完成：

1. **聚合**：日历、待办、天气、新闻 RSS、家庭留言。
2. **摘要**：LLM 生成「今日简报」——只保留与今天相关、可执行的 3~5 条。
3. **排版**：按模板生成 1bpp 画面（文字换行、图标、分区），输出 FFSP 屏幕包（整帧或区域增量）。
4. **去重**：同一内容不重复展示；低优先级内容进入轮换池。

### 6.2 个性化与记忆

- 用户画像：作息、关注主题、常看卡片、常忽略内容。
- 记忆：记住「周报待办」「孩子放学时间」「常去的路线」等长期信息。
- 反馈：用户在 App 里点「有用/没用」，用于调整摘要权重。
- 隐私：原始日历/邮件只在云端处理，设备只落盘渲染后的画面与少量文本缓存。

### 6.3 语音（可选，P2）

- 硬件预留 U6 音频接口（`docs/datasheet/ES8311+NS4150B CODEC 音频模块`）。
- 建议路径：设备录音 → 手机/云端 ASR → LLM → 文字结果回传 → 屏幕显示。
- 不在设备端做唤醒词与 LLM 推理，避免功耗与算力问题。

### 6.4 AI 边界

- 不自动执行支付、发送消息等有副作用操作。
- 所有 AI 生成内容标注「AI 摘要」与生成时间。
- 断网时回退到缓存内容与本地模板，不显示空白。

## 7. 刷新策略（本产品的关键技术点）

### 7.1 三种刷新

| 模式 | 用途 | 驱动接口 | 特征 |
|---|---|---|---|
| 整屏全刷 | 切卡片、换日、首次上电、残影清理 | `hal_epd_display_film()` | 有闪白，约数秒 |
| 整屏差分 | 同版式内容整体变化（如照片换图） | `hal_epd_display_film_partial()` | 无闪白，只驱动变化像素 |
| 窗口局部 | 时间、倒计时、状态栏、单个卡片 | `hal_epd_partial_update()` | 只刷新矩形区域，最快 |

> 差分/局部刷新依赖屏上已有整屏基准帧；深睡/断电后必须先全刷一次。驱动已实现这三种路径（`hal_epd_750.c`）。

### 7.2 刷新调度

设备端不再维护页面排版，只执行服务端 FFSP 区域表给出的刷新策略：

- 区域表为每个区域声明 `refresh` 与版本号。
- 同一次唤醒内：
  - 只有单区域变化 → `hal_epd_partial_update()` 窗口刷新
  - 多区域且总面积 < 40% → 合并外接矩形或多个窗口
  - 全屏内容变化 → `hal_epd_display_film_partial()` 整屏差分
  - 版式变化 / 首次 / 残影清理 → `hal_epd_display_film()` 整屏全刷
- 深睡后屏上内容保留，但控制器 RAM 的旧帧基准不可信，下一次唤醒的第一帧必须整屏全刷（或整屏差分后 N2OCP 重建基准）。
- 同一帧内多次更新由服务端合并，设备不重复刷新。

### 7.3 残影管理

- 服务端在 FFSP 区域表里安排周期性整屏全刷（如每 30~60 分钟，或夜间固定一次）。
- 局部刷新区域由服务端控制，避免长期只刷同一小块。
- 设备按区域表的 `refresh` 字段执行，不在本地猜。

### 7.4 电源与唤醒

- 电池模式：定时唤醒（如每 1/5/15/30/60 分钟，可配）→ 拉高 GPIO9 → WiFi 连接 → 拉取 FFSP → 上屏 → EPD deep sleep → 断电深睡。
- 常电模式：可保持 3V3_C 供电和 WiFi 长连接，按分钟级拉取/局部刷新；也可沿用定时唤醒以省电。
- 深睡前必须等 BUSY 释放并让 EPD 进入 deep sleep，再断开 3V3_C。
- 按键唤醒后优先读 SD 缓存，未命中再联网请求目标页；都失败则保持当前画面。

### 7.5 时钟新鲜度

- 纯 SSR 下，屏上时间只在「唤醒并成功上屏」时更新；电池模式的新鲜度 = 唤醒周期。
- 如需分钟级走时，只有两条路：缩短唤醒周期（功耗换新鲜度），或常电模式保持在线。
- 这是产品取舍，不在设备端做本地时钟叠加。

## 8. 端到端数据链路

设备不解析 `.film`，SSR 主链路不落盘；SD 只做可选缓存。整条链路围绕一个「屏幕包」：

```
手机 App / Web
   │  配置内容源、账号、卡片顺序
   ▼
云端 AI 服务
   │  聚合 → LLM 摘要 → 模板排版 → 800×480 1bpp
   ▼
FFSP 屏幕包（整帧或区域增量，含版本/CRC）
   │  HTTPS 拉取（BLE 仅配网/控制/OTA）
   ▼
设备 service_screen：流式下载到 PSRAM → 校验 → 上屏 → NVS 记录版本 → 可选写 SD 缓存
```

- **配网**：BLE（复用现有 `0x30~0x38` WiFi 配网命令）。
- **内容**：HTTPS GET，请求带当前 `page_id/version`；服务端无变化返回 `204`。
- **状态**：NVS 只存 `page_id/version/last_ok`；SD 可选缓存最近成功页面与动画帧。
- **离线**：优先读 SD 缓存页；无缓存则电子纸保持最后一帧；不做本地重绘。
- **失败**：下载或校验失败直接丢弃，保持原画面。

## 9. 屏幕包格式（FFSP）与协议

### 9.1 为什么不用 `.film`

| 维度 | `.film` | SSR 需要 |
|---|---|---|
| 定位 | 照片/动图帧播放容器 | 页面同步与增量更新 |
| 文件头 | 32B，颜色表/格式/帧数 | 版本、区域表、校验 |
| 尺寸 | 固定整帧 | 可变大小区域包 |
| 更新 | 整帧替换 | 按区域增量 + 请求版本 |
| 校验 | 无 | header/region CRC |
| 存储 | 依赖文件系统/SD | FFSP 内存流式；SD 仅可选缓存 |

结论：信息屏不复用 `.film`，定义新的 **FFSP（FrameFilm Screen Package）**；冰箱贴继续使用 `.film`。

### 9.2 FFSP v1 布局（小端）

**Header（32 B）**

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0x00 | magic | 4B | `"FFSP"` |
| 0x04 | version | u8 | 包格式版本 = 1 |
| 0x05 | flags | u8 | bit0=full，bit1=delta，bit2=compressed |
| 0x06 | pixel_format | u8 | 0 = mono1（1=黑，MSB 在前） |
| 0x07 | panel_id | u8 | `0x09` |
| 0x08 | width | u16 | 800 |
| 0x0A | height | u16 | 480 |
| 0x0C | page_id | u16 | 页面编号 |
| 0x0E | region_count | u16 | 区域数 |
| 0x10 | base_version | u32 | 增量包基于的版本；全量 = 0 |
| 0x14 | target_version | u32 | 应用后的版本 |
| 0x18 | payload_size | u32 | 所有区域数据总字节数 |
| 0x1C | header_crc32 | u32 | header（本字段置 0）的 CRC32 |

**Region Entry（24 B × region_count）**

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0x00 | x | u16 | 区域左上角 X |
| 0x02 | y | u16 | 区域左上角 Y |
| 0x04 | w | u16 | 区域宽（像素） |
| 0x06 | h | u16 | 区域高（像素） |
| 0x08 | codec | u8 | 0 = raw 1bpp；1 = RLE（v1 预留） |
| 0x09 | refresh | u8 | 0=window，1=diff，2=full |
| 0x0A | reserved | u16 | 0 |
| 0x0C | data_offset | u32 | 相对 payload 起点 |
| 0x10 | data_size | u32 | 该区域数据字节数 |
| 0x14 | data_crc32 | u32 | 区域数据 CRC32 |

**Payload**：按区域顺序拼接的 1bpp 位图，每行 `(w+7)/8` 字节，MSB 在前，1=黑。

- v1 不做压缩，`codec=0`；RLE 作为后续兼容扩展。
- 全量包 `flags.full=1`，通常只有一个覆盖 800×480 的区域。
- 增量包 `flags.delta=1`，只包含变化区域。

### 9.3 版本与增量协议

```
GET /v1/screen?device_id=<id>&panel=0x09&page=<n>&base=<version>
```

| 响应 | 含义 | 设备动作 |
|---|---|---|
| 200 + FFSP | 有更新 | 下载 → 校验 → 上屏 → 提交版本 |
| 204 No Content | 无变化 | 直接深睡，屏保持原画面 |
| 409 Conflict | base 版本失效 | 用 `base=0` 重发，服务端返回全量 |
| 401 / 403 | 未授权 | 提示配网/绑定 |

- 设备只在**全部校验通过后**才开始上屏；任何失败都保持当前画面。
- 上屏成功后把 `target_version` 写入 NVS；断电/重启后从该版本继续请求。
- 若 NVS 丢失或版本不连续，设备用 `base=0` 请求全量，服务端无需保存每台设备的历史帧。
- 服务端可保留每台设备最近一帧用于计算增量；设备侧不需要旧帧。

### 9.4 BLE 命令

- 保留：`0x42` 屏幕参数、`0x30~0x38` 配网、`0x10~0x13` OTA。
- 信息屏**不再使用** `0x00~0x08` 文件传输；SD 由设备内部缓存/素材使用，不依赖 BLE 传图。
- 可选控制：`0x5A` 查询当前页/版本、`0x5B` 切页/强制刷新。
- 所有新增命令必须同步 `docs/blecmd/blecmd_protocol.md`、`ble-utils.js`、`frame.js`。

## 10. 固件架构演进

### 10.1 分层（薄客户端）

```
service_screen（唤醒后拉取/校验/上屏状态机）      ← 新增
  ├─ screen_pkg（FFSP 解析、CRC 校验）
  ├─ screen_http（HTTPS 流式下载到 PSRAM）
  └─ storage_cache（SD：离线页/动画帧/日志，可选）
film_service（BLE / OTA / WiFi / 参数）
film_hal（EPD / 按键 / LED / 电池 / 电源 / SD）
film_sys（配置 / 日志 / 初始化）
```

- 不引入 LVGL / `film_app` / `film_ui`，也不做本地页面排版。
- **保留 `hal_sd` 与 SD 初始化**；挂载失败不能阻塞 SSR，也不能自动格式化用户卡。
- **替换** `service_file` / `service_film` 为通用的 `storage_cache`：只做缓存与素材，不再绑定 `.film` 与固定文件尺寸。
- `service_screen` 是唯一的信息屏逻辑：请求 → 下载 → 校验 → 上屏 → 记录版本；SD 只做可选缓存。
- 保持三层依赖不变；`service_screen` / `storage_cache` 属于 `film_service`。

### 10.2 FFSP 播放模型

```c
typedef struct {
    uint16_t x, y, w, h;
    uint8_t  codec;      /* 0=raw 1bpp */
    uint8_t  refresh;    /* 0=window 1=diff 2=full */
    uint32_t data_offset;
    uint32_t data_size;
    uint32_t data_crc32;
} ffsp_region_t;
```

- 设备只做：整包下载到 PSRAM → 校验 header/region CRC → 按 `refresh` 调 HAL。
- 全量包 = 一个全屏区域 + `refresh=full`；增量包 = 若干窗口区域。
- 按键切页 = 优先读 SD 缓存；未命中再发起页面请求；离线且未命中时保持当前画面。
- 内置 1~2 张兜底卡（未配网/离线/低电）直接编译进 Flash，不依赖 SD。
- SD 缓存目录建议：`/info/pages`、`/info/anim`、`/info/assets`、`/info/log`；写入用 `.tmp` + rename，启动时清理残留。

### 10.3 服务端渲染器

- 输入：用户数据源、AI 摘要、页面模板。
- 输出：FFSP 屏幕包（整帧或区域增量），不再输出 `.film`。
- 复用 Pillow 渲染 1bpp；模板与字体都在服务端，改版不需要 OTA。
- 服务端按 `base_version` 计算变化区域；无变化返回 `204`。

### 10.4 分阶段

| 阶段 | 目标 | 产出 |
|---|---|---|
| P0 | 基础可用 | 现有基础工程：全刷/差分/局部刷新、按键、BLE、电池/休眠 |
| P1 | 薄客户端 | 保留 SD + `storage_cache`；新增 `service_screen` + FFSP + HTTPS 拉取；离线页/动画帧缓存 |
| P2 | AI 内容 | 服务端模板渲染（AI 简报/日程/天气/新闻）、增量更新、离线兜底 |
| P3 | 增强 | 语音问答（U6 音频）、家庭留言、传感器/环境数据 |

### 10.5 SD 的角色（保留初始化，不阻塞主链路）

SD 不作为 SSR 的必需路径，但以下场景值得保留：

| 用途 | 说明 |
|---|---|
| 离线页面缓存 | 最近 N 页的 FFSP 包；断网时按键仍可切换已缓存页面 |
| 桌宠动画帧 | 预下载的精灵/动画序列直接从 SD 播放，播放时不需要联网 |
| 本地素材 | 宠物皮肤、图标、照片、音效等 |
| 日志/诊断 | 运行日志、崩溃信息、刷新耗时统计 |
| 大文件中转 | PSRAM 不足时的下载暂存（可选） |
| OTA 暂存/回滚 | 可选，取决于 OTA 方案 |

落地约束：

- 上电初始化顺序保持 `GPIO9 上电 → SD 挂载`；挂载失败只降级为“无缓存”，不能阻塞启动或联网。
- **不要 `format_if_mount_failed`**；格式化只能由用户显式触发（BLE `0x2B` 或 App）。
- 缓存写入用 `.tmp` + rename，启动时清理残留 `.tmp`；目录按 `/info/pages`、`/info/anim`、`/info/assets`、`/info/log` 划分。
- 深睡前 `hal_sd_deinit()`；SD 电源在 `3V3_C` 上，随 `GPIO9` 一起断电。
- 缓存淘汰按容量/时间（如最多 8 页、动画包最多 3 套），避免写满卡。

## 11. 关键用户流程

### 11.1 首次配网

1. 开机显示配网卡（二维码 + 设备名）。
2. 手机 BLE 连接 → 发送 WiFi 账号密码。
3. 设备联网成功 → 显示配对码 → App 绑定。
4. 拉取第一份首页内容 → 整屏全刷。

### 11.2 每日早晨更新

1. 定时唤醒 → 拉高 GPIO9 → EPD/WiFi 初始化。
2. 请求 FFSP，带当前 `page/version`；`204` 则直接深睡，屏保持原画面。
3. 有变化：下载整包到 PSRAM → 校验 → 上屏（全刷/差分/窗口）→ NVS 记录版本 → 可选写 SD 缓存。
4. 到达更新间隔或按键后深睡；电池模式不做本地分钟级计时。

### 11.3 按键交互（单键）

| 操作 | 行为 |
|---|---|
| 单击 | 下一页（优先 SD 缓存，未命中联网） |
| 双击 | 上一页（优先 SD 缓存，未命中联网） |
| 长按 | 强制同步当前页 |
| 超长按（可选） | 进入/退出专注模式或休眠确认 |

> 有 SD 缓存时，断网也能切已缓存的页面；未缓存页面联网失败则保持当前画面。与冰箱贴的「长按=休眠」是否统一需产品确认。

### 11.4 低电/断网

- 电量 < 20%：状态栏提示，降低唤醒/拉取频率。
- 电量 < 5%：显示内置低电卡后深睡，按键可唤醒查看。
- 断网/服务器不可用：优先显示 SD 缓存的当前页；无缓存则保持最后一次成功画面，不白屏。
- 首次配网前：显示内置配网卡（设备名 + 二维码）。

## 12. 视觉与排版规范（1-bit）

- **栅格**：12 列，边距 24px，卡片间距 16px。
- **字号**：时间 64~96px；标题 24~32px；正文 16~20px；注释 12~14px。
- **字体**：中文子集字库（按页面文案生成），英文/数字用等宽或几何无衬线。
- **对比**：纯黑/纯白为主；灰阶用 2×2 或 4×4 有序抖动，避免细碎噪点。
- **图标**：16/24/32px 单色位图，统一线宽与圆角。
- **禁止**：大面积反白正文、低对比灰色文本、超过 3 种字号混排。

## 14. 风险与待验证项

1. **UC8179 差分波形**：当前局部刷新使用 OTP 差分 bank（强制温度 0x6E），需在 GDEM075T41WT 实屏验证刷新质量与残影；不同批次可能需要调整温度 bank。
2. **局部窗口坐标**：PTL 的 x 以像素计且按 8 对齐，需实屏验证窗口边界。
3. **单键交互**：单击/双击/长按的时间窗口需按手感调参（双击窗口 350ms 起）。
4. **服务端依赖**：纯 SSR 下服务端不可用只能显示缓存；需要可用性监控与兜底卡。
5. **WiFi 重连**：每次深睡唤醒都要重连 WiFi；需实测连接耗时与失败重试策略。
6. **流量与功耗**：单帧 47KB，按唤醒频率估算日流量；电池模式需实测整机电流；SD 不使用时应 deinit 省电。
7. **整包校验**：FFSP 需做 header CRC、区域 CRC 与总长度校验，避免半包/花屏；NVS 版本只在上屏成功后提交。
8. **内容格式**：FFSP 区域刷新协议尚未在服务端与固件同时落地，需并行验证。
9. **时钟新鲜度**：电池模式屏上时间只在唤醒时更新，属于产品预期，不是缺陷。
10. **SD 可靠性**：缓存写入用 `.tmp` + rename；挂载失败降级为无缓存；**不要 `format_if_mount_failed`**，格式化只能由用户显式触发。
11. **按键离线**：缓存未命中且断网时按键无法切页，需给出明确反馈（如 LED 提示）。
