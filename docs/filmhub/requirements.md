# film-hub（片库枢纽）需求文档

> 版本：v1.1（已确认）
> 日期：2026-08-07
> 状态：需求采集完成，用户已确认；技术方案待设计

## 1. 项目概述

film-hub 是 FrameFilm 墨水屏项目的**局域网后端 + 管理前端**，为墨水屏设备提供 film 内容分发、设备管理、模板 / 轮播流等功能。

- 项目目录：`server/`（仓库顶层，与 `firmware/`、`tools/` 平级）
- 部署范围：**局域网内使用，暂不部署到公网**

## 2. 总体需求

### 2.1 前后端架构
- 需要有后端 + 有前端
- 在局域网内使用，暂不部署到公网

### 2.2 用户登录
- 需要有用户登录功能
- 目前先做成**单用户登录**

### 2.3 前端体验
- 前端需要做到**精致、好看、炫酷、好用**

## 3. 详细功能需求

### 3.1 设备 film 获取 API（功能需求 1）
- 后端为设备提供 film 获取 API（设备端功能及实现）
- 设备通过 HTTP 获取 film 二进制文件
- 需兼容双版本屏幕：渲染画布均为竖版（基础版 400×600 / Pro 版 528×792），film 文件头为固件驱动横屏分辨率（600×400 / 792×528），像素采样方式不同（基础版列优先翻转 / Pro 版行优先），转换参数化
- **设备类型设置**：工具（前端）通过设置设备类型（basic/pro）获得对应画布（竖屏 400×600 / 528×792）与采样方式，后端按设备类型执行对应转换

### 3.2 设备心跳 API（功能需求 2）
- 设备端定时监听（轮询）心跳 API
- 心跳 API 支持**下发设备控制指令**，包括：
  - 设备功能配置
  - 发起设备 film WiFi 获取
  - 其他控制指令
- **API 设计待设计**（请求/响应格式、指令下发机制）

### 3.3 Web 端模板库与轮播流（功能需求 3）

**模板库**
- 支持若干**内置模板**
- 支持**自定义模板**（实现方法需设计）
- **每个模板支持选择渲染算法**（即生成 film 时的渲染/转换参数，如抖动算法类型、抖动强度、对比度等）

**轮播流**
- 支持通过**拖动**等方式创建轮播流
- 两种轮播方式：
  1. **服务端主动推送**：服务端按轮播流中每个模板的间隔推送图片
  2. **设备主动获取**：设备定时休眠唤醒 → 调用 film 下载 API → 下载完一次后，后端按轮播流填充下一个图片
- 轮播流创建支持**相对时间**与**绝对时间**指定：
  - 相对时间：可指定某个模板**定时更新**（按间隔）
  - 绝对时间：可指定某个模板**定点更新**（按具体时刻）
- 注：轮播流部分后续再继续完善

**设备状态显示**
- 设备开启心跳监听后，可显示设备状态：
  - 设备实时电量
  - 设备功能状态
  - 设备内文件列表
  - 等

### 3.4 批量相册导入和管理（功能需求 4）
- 支持批量相册导入
- 支持相册管理（增删改查等）

### 3.5 AI API 接入（功能需求 5）
- 支持 AI 的 API 接入
- 最好能实现 **AI 创建自定义模板**
- 有条件可实现 **AI 生图模板**功能

### 3.6 基础模板（功能需求 6）
以下为基础模板：
- **相册模板**：可指定批量照片在模板内轮流刷新
- **日历模板**
- **备忘录模板**
- **天气模板**
- **冰箱食材管理模板**
- **今日运势模板**

## 6. 约束与注意事项

- film 文件格式规范见 `docs/film/film.md`（32B 文件头 + 4bit/像素）
- 双版本画布均为竖版：基础版 400×600（film 固定 120032 字节），Pro 版 528×792（film 固定 209120 字节）；文件头分辨率分别为 600×400 / 792×528
- 设备下载要求：`Content-Type: application/octet-stream`，30 秒超时，支持重定向
- 跨端一致性：BLE 命令常量、film 颜色编码需三端同步；本项目新增一端，转换算法必须与现有 JS 实现保持一致
