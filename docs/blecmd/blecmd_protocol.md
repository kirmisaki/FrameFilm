# FrameFilm BLE 通信协议详细规范

## 1. 概述

本文档定义 FrameFilm 设备与上位机之间的 BLE（蓝牙低功耗）通信协议。协议采用 GATT 方式进行数据传输，支持 FILM 文件传输、OTA 固件升级、设备控制、WiFi 网络配置等功能。

## 2. 协议框架

### 2.1 BLE GATT 通道

设备提供 **3 个 GATT 数据通道** 用于与上位机通信：

| 通道 | 用途 | 方向 | 说明 |
|------|------|------|------|
| CH1 (CMD) | 命令通道 | 双向 | 用于发送命令和接收响应 |
| CH2 (DATA) | 数据通道 1 | 上行 | 用于大数据量传输（预留） |
| CH3 (DATA) | 数据通道 2 | 上行 | 用于大数据量传输（预留） |

### 2.2 数据包结构

所有命令和数据均采用统一的数据包格式：

```
+--------+--------+--------+----------+--------+
|  HEAD  |  CH    |  LEN   |  DATA    |  SUM   |
+--------+--------+--------+----------+--------+
|  1 B   |  1 B   |  1 B   |  N B     |  1 B   |
+--------+--------+--------+----------+--------+
```

| 字段 | 长度 | 说明 |
|------|------|------|
| HEAD | 1 B | 帧头，固定值 `0x55` |
| CH | 1 B | 通道号，标识命令类型 |
| LEN | 1 B | DATA 字段的长度（字节数） |
| DATA | N B | 数据内容，长度由 LEN 指定 |
| SUM | 1 B | 校验和，`HEAD + CH + LEN + DATA` 所有字节之和 |

## 3. 通道定义

### 3.1 FILM 文件传输通道 (0x00 - 0x08)

| 通道 | 名称 | 方向 | 数据格式 | 说明 |
|------|------|------|----------|------|
| 0x00 | FILE_NAME | 下行 | 字符串 | 文件名或相对路径（含 `/` 时按显式路径写入），ASCII 编码 |
| 0x01 | FILE_LEN | 下行 | uint32 (Big-Endian) | 文件大小 |
| 0x02 | FILE_DATA | 下行 | N bytes | 文件数据内容 |
| 0x03 | FILE_START | 下行 | 无 | 开始传输 |
| 0x04 | FILE_STOP | 下行 | 无 | 结束传输 |
| 0x05 | FILE_DELETE | 下行 | uint8 | 删除指定 ID 文件 |
| 0x06 | FILE_LIST | 上行 | 响应数据包 | 查询文件列表 |
| 0x07 | FILE_DISPLAY | 下行 | uint8 | 显示指定 ID 文件 |
| 0x08 | FILE_DISPLAY_GET | 上行 | uint8 | 获取当前显示文件 ID |

### 3.2 OTA 升级通道 (0x10 - 0x13)

| 通道 | 名称 | 方向 | 数据格式 | 说明 |
|------|------|------|----------|------|
| 0x10 | OTA_LEN | 下行 | uint32 (Big-Endian) | OTA 文件大小 |
| 0x11 | OTA_DATA | 下行 | N bytes | OTA 数据内容 |
| 0x12 | OTA_START | 下行 | 无 | 开始 OTA |
| 0x13 | OTA_STOP | 下行 | 无 | 结束 OTA |

### 3.3 设备控制通道 (0x20 - 0x2B)

| 通道 | 名称 | 方向 | 数据格式 | 说明 |
|------|------|------|----------|------|
| 0x20 | CTRL_MODE | 下行 | uint8 | **[已废弃]** Film 模式切换，收到后忽略并打日志；播放模式改由图片 app 参数通道 (0x45) 设置 |
| 0x21 | CTRL_MODE_GET | 上行 | uint8 | **[已废弃]** 查询当前模式，固定回 `0xFF`；播放模式改由图片 app 参数通道 (0x46) 查询 |
| 0x22 | CTRL_RESET | 下行 | 无 | 重置设备到出厂设置 |
| 0x23 | CTRL_PWRREAD | 上行 | uint8 | 获取电量 (0-100%) |
| 0x24 | CTRL_REBOOT | 下行 | 无 | 重启设备 |
| 0x25 | CTRL_SLEEPONOFF | 下行 | uint8 | 休眠模式开关 (0: 关闭, 1: 开启) |
| 0x26 | CTRL_SLEEPONOFF_GET | 上行 | uint8 | 查询休眠模式开关状态 |
| 0x27 | CTRL_SLEEPMODE | 下行 | uint8 | 定时唤醒开关 (0: 关闭, 1: 开启) |
| 0x28 | CTRL_SLEEPMODE_GET | 上行 | uint8 | 查询定时唤醒开关状态 |

| 0x2A | CTRL_SLEEPMODE_TIME_GET | 上行 | uint32 (Big-Endian) | 查询定时唤醒时间 |
| 0x2B | CTRL_SDRESET | 下行 | 无 | SD卡格式化 (`v0.2`新增) |

| 0x36 | FILM_API_URL | 下行 | string | 设置 film 下载 API 地址（最大127字符） |
| 0x37 | FILM_API_URL_GET | 上行 | string | 查询 film API 地址 |
| 0x38 | WIFI_CONNECT | 下行 | 无 | 连接 WiFi |

### 3.5 屏幕信息通道 (0x42)

| 通道 | 名称 | 方向 | 数据格式 | 说明 |
|------|------|------|----------|------|
| 0x42 | SCREEN_RESOLUTION_GET | 上行 | ID(1B) + uint16 ×2 (Big-Endian) | 查询屏幕面板 ID 与分辨率（宽、高） |

### 3.6 App 控制通道 (0x4B ~ 0x4C)

> **为何跳号**：0x43 / 0x44 已由 Dock 底座固件占用（键盘键值设置/查询，见 §3.8），
> 故 App 控制通道排在 App 参数通道（0x45 ~ 0x4A）之后，使 `0x45 ~ 0x4C` 成为连续的 App 通道区间。
> 冰箱贴固件不使用 0x43 / 0x44。
>
> 本通道的远程切换（0x4B）**在所有机型/屏幕上均有效**，与面板无关。
> 它只受两点约束：
> 1. `app_id` 必须已注册。注册集合由 `sys_cfg.h` 的 `SYS_APP_SWITCH_MODE` 决定：
>    `FULL` 注册 4 个 app；`NONE`/`SIMPLE` 仅注册 图片(0x00) 与 模板(0x01)，切到 0x02/0x03 会被忽略。
> 2. 越界 `app_id` 被忽略（设备侧打日志 `switch ignored: app id=... not registered`）。
>
> 按键交互能力另由 `SYS_APP_SWITCH_MODE` 决定（与远程切换解耦）：
> `NONE` 关闭按键切换 / `SIMPLE` 简易（图片 ↔ 最近推送的 app）/ `FULL` 全功能（长按确认键进封面菜单）。
> `FULL` 需要 3.7" 屏（面板 ID 0x02）提供封面菜单渲染能力，在其余屏幕会自动降级为 `SIMPLE`。

| 通道 | 名称 | 方向 | 数据格式 | 说明 |
|------|------|------|----------|------|
| 0x4B | APP_SWITCH | 下行 | uint8 | 切换 app（app_id 见下表），设备不回复 |
| 0x4C | APP_CURRENT_GET | 上行 | uint8 | 查询当前 app（返回 app_id，0xFF 表示未知） |

| app_id | 应用 |
|--------|------|
| 0x00 | 图片 image |
| 0x01 | 模板 template |
| 0x02 | 时钟 clock |
| 0x03 | 动图 animation |

### 3.7 App 参数通道 (0x45 ~ 0x4A) `v1.7`新增

> app 各自的可配置参数（播放模式、定时间隔、网络拉取等）通过本通道读写，与屏幕面板无关。
> 通道号与 app 的绑定在 **app 注册时**建立：约定 `param_ch` 为设置通道，查询通道 = `param_ch + 1`。
> 时钟 app **无参数，不占通道**。
>
> 路由原则：**按 app 归属路由，不按当前 app**。手机可以在显示图片时预设动图/模板参数，设备照样写入目标 app（目标 app 无需处于运行态）。

| 通道 | 名称 | 方向 | 数据格式 | 说明 |
|------|------|------|----------|------|
| 0x45 | APP_IMAGE_PARAM | 下行 | TLV 列表 | 图片 app 参数设置，设备不回包 |
| 0x46 | APP_IMAGE_PARAM_GET | 上行 | TLV 列表 | 图片 app 参数查询 |
| 0x47 | APP_TEMPLATE_PARAM | 下行 | TLV 列表 | 模板 app 参数设置，设备不回包 |
| 0x48 | APP_TEMPLATE_PARAM_GET | 上行 | TLV 列表 | 模板 app 参数查询 |
| 0x49 | APP_ANIM_PARAM | 下行 | TLV 列表 | 动图 app 参数设置，设备不回包 |
| 0x4A | APP_ANIM_PARAM_GET | 上行 | TLV 列表 | 动图 app 参数查询 |

**TLV 结构**（DATA 部分）：

```
[TAG(1B)][LEN(1B)][VALUE(LEN B)] [TAG(1B)][LEN(1B)][VALUE(LEN B)] ...
```

**通用约定**：

1. **增量设置**：一包可携带任意个 TLV，只发想改的字段即可，未出现的字段保持原值。
2. **未知 TAG 跳过**：设备不认识的 TAG 按 `LEN` 安全跳过，不报错。
3. **LEN 不符**：某 TAG 的 `LEN` 与定义不符时，仅跳过该 TAG（打警告），**不整包丢弃**。
4. **SET 不回包**：设置通道（0x45/0x47/0x49）静默生效，需要确认请用对应 GET 通道回读。
5. **GET 空包**：目标 app 未注册或 `LEN=0` 时，返回 `LEN=0` 的空数据包。
6. **立即生效**：设置后参数立即写入并持久化（NVS）；涉及画面刷新的字段（如 `file_id`）仅在目标 app 为当前 app 时刷新屏幕。
7. **单包长度限制**：下行 SET 经设备事件总线投递，**单包 DATA 建议不超过 15 字节**（超出会被截断）。字段较多时请拆分为多包下发，每包可只含一个 TLV。

### 3.8 Dock 键盘键值通道 (0x43 ~ 0x44，仅 Dock 底座)

> 这两个通道**只在 Dock 底座固件**（`firmware/frame_film_dock/`）中实现。Dock 的按键不操作本机，
> 而是作为 **PC 键盘**：单击/双击/长按按配置好的 HID 键值发送。冰箱贴固件不使用 0x43 / 0x44
> （其 App 通道为 0x45 ~ 0x4C），对这两个命令号不做处理。
>
> 报文格式、校验和与其他通道完全一致；Dock 的 BLE 与 USB(CDC) 共用同一套命令解析，
> 两条链路均可下发，应答按来源链路原路返回。

| 通道 | 名称 | 方向 | 数据格式 | 说明 |
|------|------|------|----------|------|
| 0x43 | KEYBOARD_KEY_SET | 下行 | 事件(1B) + 修饰键(1B) + 键数(1B) + 键码(nB) | 设置某事件的 HID 键值，设备不回复 |
| 0x44 | KEYBOARD_KEY_GET | 上行 | [修饰键(1B) + 键数(1B) + 键码(6B)] × N | 查询键值，最多返回单击/双击/长按三组 |

**事件取值**：`0` 单击（SHORT）/ `1` 双击（DOUBLE）/ `2` 长按（LONG）。

**修饰键**：HID 修饰键位掩码 —— bit0 Ctrl / bit1 Shift / bit2 Alt / bit3 GUI，`0x00` 表示无修饰键。

**键码**：HID Usage ID 列表（`0x04`=A …… `0x29`=Esc），组合键时按顺序填入，
单组最多 6 个（`SERVICE_KEY_MAX_NUM`）；键数为 `0` 表示该事件不发送任何按键。

## 4. 命令详解

### 4.1 通用规则

1. **校验和计算**：`SUM = HEAD + CH + LEN + 所有 DATA 字节`（只取低 8 位）
2. **字符串格式**：文本使用 ASCII 编码，以 `\0` 结尾
3. **整数格式**：多字节整数采用 Big-Endian（大端序）编码
4. **响应延迟**：列表查询时每条响应间隔 10ms，避免阻塞

### 4.2 FILM 文件传输

#### 4.2.1 传输流程

```
客户端                              设备
  |                                  |
  | -------- FILE_START ------------> | (1) 开始传输
  |                                  |
  | -------- FILE_NAME ------------> | (2) 发送文件名
  |                                  |
  | -------- FILE_LEN ---------------> | (3) 发送文件大小
  |                                  |    (4) 打开文件准备写入
  |                                  |
  | -------- FILE_DATA 1 -----------> | (5) 发送数据块 1
  | -------- FILE_DATA 2 -----------> | (6) 发送数据块 2
  | -------- FILE_DATA N -----------> | (7) 发送数据块 N
  |                                  |
  | -------- FILE_STOP -------------> | (8) 结束传输
  |                                  |    (9) 保存文件
```

#### 4.2.2 状态机

```
          ┌────────────────────────────────────────────────────────┐
          │                                                         │
          ▼                                                         │
    ┌──────────┐                                                    │
    │   IDLE   │◄───────────────────────────────┐                   │
    └────┬─────┘                                │                   │
         │ FILE_START                           │ (完成)            │
         ▼                                       │                   │
    ┌──────────┐                                │                   │
    │ STARTED  │───────────────────────────────┘                   │
    └────┬─────┘                                │                   │
         │ FILE_NAME                            │ (错误)            │
         ▼                                       │                   │
    ┌──────────────┐                            │                   │
    │  RECV_NAME   │───────────────────────────┘                   │
    └──────┬───────┘                                                │
           │ FILE_LEN                                               │
           ▼                                                        │
    ┌──────────────┐                                                │
    │  RECV_LEN    │                                                │
    └──────┬───────┘                                                │
           │ FILE_DATA                                              │
           ▼                                                        │
    ┌──────────────┐                                                │
    │  RECV_DATA   │ ───────────────────────────────> FILE_STOP ────┘
    └──────────────┘
```

#### 4.2.3 详细命令

##### FILE_START (0x03)

**方向**：下行（客户端 → 设备）

**数据**：无

**说明**：开始 FILM 文件传输，重置传输状态，清空缓冲区。

---

##### FILE_NAME (0x00)

**方向**：下行（客户端 → 设备）

**数据格式**：

```
+--------+--------+--------+ ... +--------+
|  NAME_LEN (1B) |  FILENAME (N B)     |
+--------+--------+--------+ ... +--------+
```

**说明**：
- NAME_LEN：文件名长度（含结尾 `\0`）
- FILENAME：ASCII 编码的文件名字符串
- 不含 `/` 时：写入当前工作目录（`/sdcard/film` 或 `/sdcard/animation`），保存完成后按帧数自动分流、刷新列表并上浮 `SYS_EVT_FILE_SAVED`
- 含 `/` 时（v1.6 起）：视为**相对 `/sdcard` 的显式路径**，写入 `/sdcard/<相对路径>`，父目录不存在时自动逐级创建；保存完成后**不**参与文件列表刷新、**不**做帧数分流、**不**上浮 `SYS_EVT_FILE_SAVED`
  - 路径不得以 `/` 开头，不得包含 `..`
  - 用于写入 app 封面等与文件列表无关的资源，例如 `app/image/cover.film`

**示例 1**：传输文件 `test.film`（普通模式）

```
HEAD    = 0x55
CH      = 0x00
LEN     = 10
DATA    = [0x74, 0x65, 0x73, 0x74, 0x2E, 0x66, 0x69, 0x6C, 0x6D, 0x00]
         "test.film\0"
SUM     = 0x55 + 0x00 + 0x0A + 0x74 + ... + 0x00 = 0x1F9 (低8位 = 0xF9)
```

**示例 2**：写入图片 app 封面（显式路径模式，写入 `/sdcard/app/image/cover.film`）

```
HEAD    = 0x55
CH      = 0x00
LEN     = 21
DATA    = "app/image/cover.film\0"
SUM     = (0x55 + 0x00 + 0x15 + 所有字符字节) & 0xFF
```

后续 FILE_LEN / FILE_DATA / FILE_STOP 流程与普通模式完全一致。

---

##### FILE_LEN (0x01)

**方向**：下行（客户端 → 设备）

**数据格式**：

```
+--------+--------+--------+--------+
|  FILE_SIZE (4 B, Big-Endian)     |
+--------+--------+--------+--------+
```

**说明**：
- FILE_SIZE：文件总大小（字节数）
- 采用 Big-Endian 编码，高字节在前

**示例**：文件大小 = 10000

```
HEX: 00 00 27 10
DEC: 10000 bytes
```

##### FILE_DATA (0x02)

**方向**：下行（客户端 → 设备）

**数据格式**：

```
+--------+--------+--------+ ... +--------+
|  DATA (N B)                        |
+--------+--------+--------+ ... +--------+
```

**说明**：
- DATA：文件数据内容
- 可分多次发送，设备会追加写入

---

##### FILE_STOP (0x04)

**方向**：下行（客户端 → 设备）

**数据**：可选（1 字节 flag）

| LEN | DATA | 含义 |
|-----|------|------|
| 0（默认，兼容旧版） | 无 | 保存完成后自动加载显示新文件 |
| 1 | `0x00` | 显式指定自动加载显示 |
| 1 | `0x01` | **静默保存**：保存并刷新文件列表，但不自动加载显示（批量上传用） |

**说明**：结束 FILM 文件传输，关闭文件句柄，完成保存。`v0.3` 新增可选 flag 参数。
默认（LEN=0）保持旧行为。批量上传场景下客户端每张携带 `0x01`，避免设备反复刷新 EPD；全部传完后由客户端显式发送 `FILE_DISPLAY (0x07)` 上屏最后一张。
旧固件不识别该参数时会忽略多余字节，按自动加载处理，兼容安全。

##### FILE_LIST (0x06)

**方向**：上行（设备 → 客户端）

**触发**：客户端发送通道为 0x06 的命令（数据为空）

**响应数据格式**（每条文件一条响应）：

```
+--------+--------+--------+----------+--------+ ... +--------+
|  HEAD  |   CH   |  LEN   |  FILE_ID | NAME_LEN | FILENAME |
+--------+--------+--------+----------+--------+ ... +--------+
|  0x55  |  0x06  | 2+N+1  |   1 B    |   1 B    |  N B     |
+--------+--------+--------+----------+--------+ ... +--------+
```

**说明**：
- FILE_ID：文件 ID（从 0 开始）
- NAME_LEN：文件名长度
- FILENAME：文件名字符串

**多文件响应**：设备会逐条发送所有文件信息，间隔 10ms。

**示例**：

```
文件列表：
ID=0: "frame1.film"
ID=1: "frame2.film"

响应包 1:
HEAD = 0x55
CH   = 0x06
LEN  = 2 + 11 = 13 (0x0D)
DATA = [0x00, 0x0B, 0x66, 0x72, 0x61, 0x6D, 0x65, 0x31, 0x2E, 0x66, 0x69, 0x6C, 0x6D]
      = [ID(0), NAME_LEN(11), "frame1.film\0"]

响应包 2:
HEAD = 0x55
CH   = 0x06
LEN  = 2 + 11 = 13
DATA = [0x01, 0x0B, 0x66, 0x72, 0x61, 0x6D, 0x65, 0x32, 0x2E, 0x66, 0x69, 0x6C, 0x6D]
      = [ID(1), NAME_LEN(11), "frame2.film\0"]
```

---

##### FILE_DISPLAY (0x07)

**方向**：下行（客户端 → 设备）

**数据格式**：

```
+--------+
|  FILE_ID (1 B)  |
+--------+
```

**说明**：
- FILE_ID：文件 ID（从 FILE_LIST 获取）
- 设备会解析 .film 文件并刷新屏幕显示

**响应**：无

##### FILE_DISPLAY_GET (0x08)

**方向**：上行（设备 → 客户端）

### 4.8 App 参数（0x45 ~ 0x4A）

#### 4.8.0 通用报文

**TLV 元素格式**（DATA 部分，可重复出现）：

```
+---------+---------+---------------+
| TAG(1B) | LEN(1B) | VALUE(LEN B)  |
+---------+---------+---------------+
```

**设置报文示例**（图片 app 设置播放模式=自动、定时间隔=30 分钟）：

```
DATA = 01 01 01  02 02 00 1E
       └─TAG=0x01 play_mode, LEN=1, 值=1(自动)
                └─TAG=0x02 auto_interval, LEN=2, 大端 0x001E=30
```

**GET 响应**：DATA 为**全部 TAG 的 TLV 顺序回填**（顺序与下方各表一致），未在当前设备支持的 TAG 不出现。

**多字节整数一律 Big-Endian**（沿用 §4.1）。

---

#### 4.8.1 图片 app 参数（0x45 / 0x46）

| TAG | 名称 | LEN | 取值 | 说明 |
|-----|------|-----|------|------|
| 0x01 | `play_mode` | 1 | `0`=手动 `1`=自动 | 自动形态由休眠开关决定（见下） |
| 0x02 | `auto_interval` | 2 | `1` ~ `120`（分钟，大端） | 自动切换间隔，仅休眠关闭时生效 |
| 0x03 | `file_id` | 4 | `0` ~ `N-1`（大端） | 设置后立即跳转显示（仅目标 app 为当前 app 时刷屏） |

**自动模式两种形态**：

- `sleep_mode=0`（休眠关闭）：**定时切换**，每隔 `auto_interval` 分钟切下一张。
- `sleep_mode=1`（休眠开启）：**开机自动切换**，每次开机（唤醒）自动切下一张。

**GET 响应长度**：`3 + 4 + 6 = 13` 字节。

**示例**：查询 → 设备回 `01 01 00  02 02 00 1E  03 04 00 00 00 03`
（play_mode=0 手动，auto_interval=30 分钟，file_id=3）。

---

#### 4.8.2 模板 app 参数（0x47 / 0x48）

| TAG | 名称 | LEN | 取值 | 说明 |
|-----|------|-----|------|------|
| 0x01 | `pull_enable` | 1 | `0`=关闭 `1`=开启 | 网络拉取开关 |
| 0x02 | `pull_interval` | 2 | `1` ~ `120`（分钟，大端） | 定时拉取间隔，仅休眠关闭时生效 |

**自动拉取两种形态**（均需 `pull_enable=1`）：

- `sleep_mode=0`（休眠关闭）：**定时自动拉取**，每隔 `pull_interval` 分钟拉取一次。
- `sleep_mode=1`（休眠开启）：**开机自动拉取**，开机时拉取一次。

**GET 响应长度**：`3 + 4 = 7` 字节。

---

#### 4.8.3 动图 app 参数（0x49 / 0x4A）

| TAG | 名称 | LEN | 取值 | 说明 |
|-----|------|-----|------|------|
| 0x01 | `play_mode` | 1 | `0`=单 film 循环 `1`=列表循环 | |
| 0x02 | `frame_ms` | 2 | `100` ~ `2000`（毫秒，大端） | 每帧停留时间（播放速度） |
| 0x03 | `loop_seconds` | 2 | `0` ~ `600`（秒，大端） | 循环间隔：一个 film 播完到播下一个的等待时间，`0`=不等待 |
| 0x04 | `file_id` | 4 | `0` ~ `N-1`（大端） | 当前播放的文件下标 |

**播放模式**：

- `0`=单 film 循环：反复播放当前文件，每轮结束按 `loop_seconds` 停顿后重播。
- `1`=列表循环：按顺序播放目录内每个 film，到末尾回绕，每轮之间按 `loop_seconds` 停顿。

**GET 响应长度**：`3 + 4 + 4 + 6 = 17` 字节。

> **注意**：`frame_ms` 下限为 `100`（与设备 100ms 心跳基准对齐，更小的值不会生效）。若一包同时下发 4 个 TAG（合计 17 字节），超出设备事件总线的投递上限，请**分包下发**（每包 1~2 个 TAG）。

### 4.9 Dock 键盘键值（0x43 / 0x44，仅 Dock 底座）

> 通道概览见 §3.8。以下命令仅 `firmware/frame_film_dock/` 实现，冰箱贴固件不支持。

#### 4.9.1 KEYBOARD_KEY_SET (0x43) - 设置按键键值

**方向**：下行（客户端 → 设备）

**数据格式**：

```
+--------+--------+--------+-----------+-----------+-----------+--------------+--------+
|  HEAD  |   CH   |  LEN   | EVENT(1B) | MODIFIER  |  KEY_NUM  | KEYCODE(nB)  |  SUM   |
+--------+--------+--------+-----------+-----------+-----------+--------------+--------+
|  0x55  |  0x43  | 3 + n  |   见 3.8   |   见 3.8   |    0 ~ 6  |    见 3.8     |  1 B   |
+--------+--------+--------+-----------+-----------+-----------+--------------+--------+
```

**说明**：设置「单击 / 双击 / 长按」中某一事件的 HID 键值，设备**不返回应答**，设置后立即持久化（NVS）。

- `LEN` 必须等于 `3 + KEY_NUM` 且 `KEY_NUM <= 6`，否则整包忽略并打警告日志（`Invalid keyboard key set`）。
- `KEY_NUM = 0` 表示该事件不发送任何按键（清除该组键值）。

**示例**：把「长按」设为 `Ctrl + Shift + Esc`

```
HEAD    = 0x55
CH      = 0x43
LEN     = 4
DATA    = [0x02, 0x03, 0x01, 0x29]   ; 事件=长按, 修饰键=Ctrl+Shift, 键数=1, 键码=Esc
SUM     = (0x55 + 0x43 + 0x04 + 0x02 + 0x03 + 0x01 + 0x29) & 0xFF = 0xCB

完整数据包: 55 43 04 02 03 01 29 CB
```

#### 4.9.2 KEYBOARD_KEY_GET (0x44) - 查询按键键值

**方向**：上行（设备 → 客户端）

**触发**：客户端发送通道为 0x44 的命令。
`LEN=0`（无数据）→ 返回单击/双击/长按**三组**；`LEN=1` 且值为事件号 → 只返回该组。

**响应数据格式**（每组固定 8 字节，按 单击 → 双击 → 长按 顺序拼接）：

```
+--------+--------+--------+---------------------+---------------------+--------+
|  HEAD  |   CH   |  LEN   |  组 1 (8 B)          |  组 2 / 组 3 ...     |  SUM   |
+--------+--------+--------+---------------------+---------------------+--------+
|  0x55  |  0x44  | 8×N    | MOD(1)+NUM(1)+KC(6) |  MOD(1)+NUM(1)+KC(6) |  1 B   |
+--------+--------+--------+---------------------+---------------------+--------+
```

**说明**：

- `LEN = 8 × 组数`（空请求 = 24，指定事件 = 8）。
- 每组 = 修饰键(1B) + 键数(1B) + 键码(6B)；键码不足 6 个时以 `0x00` 补齐，长度恒定，客户端可按 8 字节步进解析。
- 键数 `0` 表示该事件未配置按键。

**示例**：查询三组（单击 = Ctrl+C，双击 = 未配置，长按 = Ctrl+Shift+Esc）

```
DATA  = 01 01 06 00 00 00 00 00   ; 单击: mod=0x01(Ctrl), num=1, keycode=C
        00 00 00 00 00 00 00 00   ; 双击: 未配置
        03 01 29 00 00 00 00 00   ; 长按: mod=0x03(Ctrl+Shift), num=1, keycode=Esc
LEN   = 24
```

## 5. 校验和计算

校验和采用 **简单求和法**（Sum Check），计算公式：

```
SUM = (HEAD + CH + LEN + DATA[0] + DATA[1] + ... + DATA[N-1]) & 0xFF
```

**示例 1**：发送 FILE_DISPLAY 命令 (显示文件 ID=3)

```
HEAD  = 0x55
CH    = 0x07
LEN   = 0x01
DATA  = [0x03]

SUM = (0x55 + 0x07 + 0x01 + 0x03) & 0xFF
    = 0x60 & 0xFF
    = 0x60

完整数据包: 55 07 01 03 60
```

**示例 2**：发送 FILE_LEN 命令 (文件大小=10000)

```
HEAD  = 0x55
CH    = 0x01
LEN   = 0x04
DATA  = [0x00, 0x00, 0x27, 0x10]

SUM = (0x55 + 0x01 + 0x04 + 0x00 + 0x00 + 0x27 + 0x10) & 0xFF
    = 0x91 & 0xFF
    = 0x91

完整数据包: 55 01 04 00 00 27 10 91
```

## 6. C 语言示例

### 6.1 构造命令包

```c
#include <stdint.h>
#include <string.h>

#define BLE_CMD_HEAD  0x55

typedef struct {
    uint8_t head;
    uint8_t ch;
    uint8_t len;
    uint8_t data[256];
} ble_cmd_packet_t;

static uint8_t ble_checksum(uint8_t* data, int len) {
    uint8_t sum = 0;
    for (int i = 0; i < len; i++) {
        sum += data[i];
    }
    return sum;
}

int build_film_display_cmd(uint8_t file_id, uint8_t* out_buf, int buf_size) {
    if (buf_size < 5) return -1;

    out_buf[0] = BLE_CMD_HEAD;
    out_buf[1] = 0x07;  // FILE_DISPLAY
    out_buf[2] = 1;    // LEN
    out_buf[3] = file_id;

    uint8_t sum = ble_checksum(out_buf, 4);
    out_buf[4] = sum;

    return 5;
}

int build_file_list_cmd(uint8_t* out_buf, int buf_size) {
    if (buf_size < 4) return -1;

    out_buf[0] = BLE_CMD_HEAD;
    out_buf[1] = 0x06;  // FILE_LIST
    out_buf[2] = 0;    // LEN
    out_buf[3] = ble_checksum(out_buf, 3);

    return 4;
}
```

### 6.2 解析响应包

```c
typedef enum {
    PARSE_STATE_HEAD,
    PARSE_STATE_CH,
    PARSE_STATE_LEN,
    PARSE_STATE_DATA,
    PARSE_STATE_SUM
} parse_state_t;

int parse_response(uint8_t* in_buf, int in_len, uint8_t* out_ch, uint8_t* out_data, int* out_data_len) {
    static parse_state_t state = PARSE_STATE_HEAD;
    static uint8_t expected_len = 0;
    static int data_idx = 0;
    static uint8_t cmd_buf[260];

    for (int i = 0; i < in_len; i++) {
        uint8_t byte = in_buf[i];

        switch (state) {
            case PARSE_STATE_HEAD:
                if (byte == BLE_CMD_HEAD) {
                    cmd_buf[0] = byte;
                    state = PARSE_STATE_CH;
                }
                break;

            case PARSE_STATE_CH:
                cmd_buf[1] = byte;
                state = PARSE_STATE_LEN;
                break;

            case PARSE_STATE_LEN:
                cmd_buf[2] = byte;
                expected_len = byte;
                data_idx = 0;
                state = (expected_len > 0) ? PARSE_STATE_DATA : PARSE_STATE_SUM;
                break;

            case PARSE_STATE_DATA:
                cmd_buf[3 + data_idx] = byte;
                data_idx++;
                if (data_idx >= expected_len) {
                    state = PARSE_STATE_SUM;
                }
                break;

            case PARSE_STATE_SUM:
                cmd_buf[3 + expected_len] = byte;
                uint8_t calculated_sum = ble_checksum(cmd_buf, 3 + expected_len);
                if (calculated_sum == byte) {
                    *out_ch = cmd_buf[1];
                    *out_data_len = expected_len;
                    memcpy(out_data, &cmd_buf[3], expected_len);
                    state = PARSE_STATE_HEAD;
                    return 1;
                }
                state = PARSE_STATE_HEAD;
                break;
        }
    }

    return 0;
}
```
