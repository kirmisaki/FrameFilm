## [2026.10.29.1] - 2026-10-29

App: 0.4.5+9

本次正式发布包含 2026-10-29 合入 main 的改动。App 升级为 **0.4.5+9**，沿用既有发行签名，最低支持 Android 9；设备显示版本保持 **3.2.5**，固件更新继续使用实际 ELF 构建指纹判断。

### WiFi 高速直传

- Android 10 及以上接入新的 SoftAP 直传链路：BLE 负责准备与控制，Ark 建立临时直连网络，App 通过 Android 系统网络请求连接，手机或平板继续提供 HTTP 文件服务，Ark 接收并写入 SD 卡。无需手动进入 WiFi 设置选择设备热点；首次授权和后续提示仍受 Android 系统及厂商实现影响。
- 固件通过 `0x59` 能力查询的 bit4 宣告支持，通过新增 `0x5C` 预留会话并异步准备 AP；Film、通用文件与 OTA 复用既有 `0x50`、`0x5A`、`0x57` 启动格式。Android 9 与不支持该能力的旧固件保留原 P2P 传输路径。
- 数据传输期间按计划暂停 BLE，减少无线共存开销。App 此时通过 HTTP 服务端统计发送进度；发送到 100% 后仍需等待设备完成写入、恢复 BLE，并通过 `0x51` 回读最终状态，才确认保存成功。
- 普通文件传输完成后恢复 BLE 服务、广播与控制连接，无需重启设备。OTA 保留 READY、显式 apply、重启重连和完整构建指纹确认流程。
- 保留 HTTP 接收与 SD 写入流水线，配套调整 WiFi 接收缓冲、TCP 接收窗口及邮箱。系统 tick 调整后，将 SD 检测与重启兜底中的固定 tick 等待改为毫秒换算，保持原来的时间语义。
- 增加新链路的准备、网络生命周期、计划内 BLE 断开、终态确认、取消和重试处理，以及对应主机测试。测速入口默认关闭，正常构建不会自动运行测速任务。

### 实测结果与方案选择

测试使用同一台平板、同一台 Ark 和同一份 `HT27A001.film`（Bad Apple，**47,347,232 字节**）。下表按设备接收、SD 写入和最终提交完成的耗时计算，单位为十进制 MB/s，不是无线协商速率，也不是 App 发送峰值。

| 连接方案 | 完整接收与落盘耗时 | 平均速度 | 结果 |
|---|---:|---:|---|
| Ark SoftAP，第 1 轮 | 41.446816 秒 | 1.142 MB/s | 保存成功，BLE 恢复，App 确认完成 |
| Ark SoftAP，第 2 轮 | 41.758863 秒 | 1.134 MB/s | 保存成功，BLE 恢复，App 确认完成 |
| 手机自动建组、Ark 接入，数据期暂停 BLE | 108.733867 秒 | 0.435 MB/s | 保存成功，但速度低于目标 |
| 手机自动建组，并对齐到 2412 MHz，数据期暂停 BLE | 114.975813 秒 | 0.412 MB/s | 实际频率已核实，仍未达到目标 |

- 当前采用两轮实测超过 **1 MB/s** 的 Ark SoftAP 链路。手机建组方向的实验源码、测试 APK 与诊断记录未作为默认功能合入。
- 对照结束后，设备与平板均恢复到通过测试的 SoftAP 固件和 APK，并核对固件完整构建指纹、APK 哈希及源码备份。
- 以上结果仅代表当前设备组合和测试条件，不保证所有手机、距离及无线环境下的最低速度。
