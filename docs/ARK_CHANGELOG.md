## [2026.11.09.1] - 2026-11-09

App: 0.4.8+12

本版修复网页串口烧录的硬件规格丢失，以及不同签名发行渠道混用导致的 App 更新问题。设备显示版本仍为 **3.2.5**；设备固件继续按硬件目标和 ELF 构建指纹识别更新。

### 网页串口烧录

- Ark 完整镜像候选保留机型名称、Flash、PSRAM 与总线信息，修复选择 N4R2 后把所需容量显示为 `NaNMB`、将正确的 ESP32-S3 / 4MB 设备误判为不匹配的问题。该错误来自网页字段遗漏，与设备原有固件版本无关。
- 保留 N4R2 / N16R8 的串口容量检查；规格数据缺失时明确提示重新获取镜像。完整镜像仍写入 `0x0`，不自动开启整片擦除。
- 更新两个相关脚本的缓存版本，避免新页面继续加载旧的目标对象结构。

### App 更新渠道与覆盖升级

- App 更新仓库由编译参数 `FRAMEFILM_APP_RELEASE_REPO` 指定，默认官方 `kirmisaki/FrameFilm`；CI 自动使用发布所在仓库，保持 APK 签名与后续应用更新处于同一渠道。设备固件始终从官方仓库获取，两者不再绑定迁移。
- `Rafael-Ikaros/FrameFilm` 的本版 APK 保留原发行签名，包名不变、版本代码从 10 提升到 12，可覆盖原 0.4.6 并保留 App 数据。不要用签名不同的上游官方 APK 代替覆盖包。
- 原 0.4.6 查询旧仓库时，11 月 4 日发布因故被撤为预发布，因而落到不含硬件清单的旧正式发布并报错。本版同时提供两个硬件 OTA 文件和完整清单，供旧客户端完成这次更新；没有将故障预发布重新转为正式版。

### 同步上游与测速代码清理

- `main` 快进同步上游至 `75158f0`，保留已合入的历史成果；纳入官方更新源、卡包、休眠与网页相关修复。
- 移除 `ARK_AP_FILE_BENCH`、`ARK_TRANSFER_BENCH`、`ARK_NETWORK_PERF` 及专用测速、HTTP sink、测试回滚入口，保留正式 SoftAP + HTTP 传输。NFC 继续仅属于配备相关硬件的主板，不作为当前 N4R2 主板能力。

验证：9 项网页串口与经典机型定向测试通过；真实 ForFilm 页面在 Edge 中完成联网获取、完整镜像校验、目标确认与模拟串口写入，无页面异常；该测试没有写入实体设备。App 更新与硬件选择共 16 项定向测试通过，应用更新仓库分别以默认和自仓库配置通过测试，静态分析通过。本机 Release APK 已验证 AOT、包名、Android 9 最低支持和与旧 0.4.6 完全相同的签名，尚未实体安装验收。两款固件均以各自 SDKCONFIG 构建成功，硬件描述与 3.2.5 显示版本核对通过；本轮没有烧录设备。

## [2026.11.07.1] - 2026-11-07

App: 0.4.7+11

本版把 2026-11-04 之后的 NFC 卡包、自动休眠与 ForFilm 在线固件相关改动一起发布。设备显示版本仍为 **3.2.5**，App 按 versionCode 更新，固件按实际 ELF 构建指纹与硬件目标匹配更新。

### NFC 卡包

- NFC 卡包使用独立 BLE 通道 `0x63~0x69`；`0x5C` / `0x5D` 恢复 SoftAP 与硬件身份的原语义，BLE 层不再按 payload 长度分流。
- 新增 NFC 总开关（持久化在 `app8` 槽位）、常驻卡模拟与 NFC 唤醒直达卡包；卡包界面中文化，原 WALLET 入口改名「卡包」，并接入 24 号字体。
- M1 卡模拟认证首帧 `0x60` / `0x61` 返回 4 字节 Nt，PICC 持续轮询；读卡成功后按返回键继续读卡。
- 修复模拟 / 读卡切换互相失效、NTAG READ 只读 16 字节、PICC 优先级、射频场 TX/RX 使能写反、读卡饿死 IDLE1、BCC0 校验与 wallet 目录创建等问题；移除冗余天线调制配置。
- st25r3916 驱动库迁入 `components/film_libs`，通过 `EXTRA_COMPONENT_DIRS` 引入并以 `WHOLE_ARCHIVE` 链接；硬件身份查询迁至 `film_sys/sys_hw`，删除 `ARK_AP_FILE_BENCH` / `ARK_TRANSFER_BENCH` / `ARK_NETWORK_PERF` 实验入口。
- ForFilm 的 NFC 卡包列表按 `start` 翻页读取全部卡片。

### 自动休眠与低功耗

- 新增自动休眠超时设置，与既有手动休眠入口并存。
- st25r3916 改用 IRQ 唤醒模拟任务，减少空闲轮询开销。

### 图像与 App

- App 接入 ColorQual 中性灰实验模式。
- App、Flutter 网页和 ForFilm 的「512 色预览 · I006」默认开启连续色调，仍可关闭以对照原 I006。沿用 I006 调色控件与 ABC9 导出。

### CI 与 ForFilm 在线固件

- Ark CI 分别提供 N4R2 与 N16R8 的完整串口镜像，正式发布时与对应 OTA 文件一起附上，供从 `0x0` 烧录和恢复设备。
- ForFilm 串口烧录可按 Ark 实物规格获取正式 Release 的完整镜像。设备控制页按硬件身份、实际 OTA 容量和 ELF 指纹检查升级，兼容不支持硬件身份查询的旧 Ark。GitHub 跨域限制下可直接下载对应附件并在页面导入校验。
- 经典 `frame_film` Pro 新增正式 Release 发布链路（tag `frame-film-v*` 或手动指定版本），由 CI 校验 12 个「硬件规格 × 屏幕」组合并生成清单与完整串口镜像；ForFilm 串口在线获取同时支持 Ark 与经典 Pro。Ark 与 Flutter 的固件更新查询忽略 `frame-film-` 开头的 Release，避免互相抢选。

### 设备文件列表对齐网页

- 设备文件按 ForFilm 的显示与使用方式常驻设置页：“FILM设置”标题右侧刷新，边框内文件列表最高 180px 并独立滚动；每行是 checkbox、ID 与单行文件名，当前显示文件用背景标记。checkbox 为单选，再次点击可取消。

### I006 预览与实屏差异

- 真实网页导出的 ABC9 文件格式有效，保持 720×480 单帧、16bitLE 与 691232 字节。保存到设备后，按文件名和活动文件 ID 确认目标；独立 fresh UART 记录确认完整 ABC9 刷新流程中的全清屏、三次 Qual 参考和关屏均完成。未做 SD 整文件内容哈希回读。

### I006 图片调节

- I006 提供抖动强度（0～5）、明暗范围拟合（0～1）、暖色收缩（0～1）、对比度与饱和度五项调节。暖色收缩默认 0.25、明暗范围拟合默认 0、扩散强度默认 1，保留原默认输出；强度 0 关闭扩散，1 为原蛇形 FS。I006 暖色值与其它算法分别保存，连续色调仍可独立切换、默认关闭。

### WiFi 高速直传

- Android 10 及以上接入新的 SoftAP 直传链路：BLE 负责准备与控制，Ark 建立临时直连网络，App 通过 Android 系统网络请求连接，手机或平板继续提供 HTTP 文件服务，Ark 接收并写入 SD 卡。无需手动进入 WiFi 设置选择设备热点；首次授权和后续提示仍受 Android 系统及厂商实现影响。
- 固件通过 `0x59` 能力查询的 bit4 宣告支持，通过新增 `0x5C` 预留会话并异步准备 AP；Film、通用文件与 OTA 复用既有 `0x50`、`0x5A`、`0x57` 启动格式。Android 9 与不支持该能力的旧固件保留原 P2P 传输路径。
- 数据传输期间按计划暂停 BLE，减少无线共存开销。App 此时通过 HTTP 服务端统计发送进度；发送到 100% 后仍需等待设备完成写入、恢复 BLE，并通过 `0x51` 回读最终状态，才确认保存成功。
- 普通文件传输完成后恢复 BLE 服务、广播与控制连接，无需重启设备。OTA 保留 READY、显式 apply、重启重连和完整构建指纹确认流程。
