# 微信小程序重构方案（对齐 ForFilm 经典版）

> 状态：1.1.0 已实现（未真机验收）
> 小程序版本：1.1.0
> 范围：仅 `tools/wechart/miniprogram` 的重写；不涉及固件、Flutter App、ForFilm 网页本体
> 决策依据：现有小程序页面层废弃重写；界面只保留 ForFilm 经典视觉，不做 Ark 主题与 Ark 专属页面；模板中心只保留「日历」

## 1. 目标

1. 按 `tools/ForFilm` 经典版的信息架构、交互语义与视觉重写小程序，替代现有 ES5 页面。
2. 完整移植 ForFilm 的图像渲染算法与编码管线，输出与网页逐字节一致的 `.film`。
3. 传输链路限定为 BLE（微信小程序能力边界），不实现 WiFi 直传。
4. 保留旧小程序中已经过真机验证的微信适配层（BLE 协议、film 编码、日历渲染），其余页面全部重写。

## 2. 范围界定

### 2.1 本次要做

| 模块 | 内容 |
|---|---|
| 连接 | 扫描、连接、断开、屏参、电量、设备信息、已连设备快速重连 |
| Frame | 拾光（相册）、定影（相机）、一言、批量、日历（独立页面） |
| Film | 选图、画布编辑（缩放/拖动/旋转）、算法与参数、1-bit 预览、导出、上传 |
| 片单 | 文件列表、切换显示、删除、当前显示查询 |
| 设置 | 休眠、定时唤醒、WiFi 配置、心跳、SD 格式化、BLE OTA、重启、恢复出厂、创作默认算法 |
| 渲染 | ForFilm 全部 6 色 4bpp 算法、8bpp 四算法、四色规则、源图适配、编码与像素排布 |

### 2.2 明确不做

| 内容 | 原因 |
|---|---|
| Ark 主题、登录动画、PRTS 视觉 | 需求明确只要经典版外观 |
| 通行证（pass）、NFC 卡包（wallet） | Ark 专属，且小程序无法写入通行证（固件只有 `0x53` 读取） |
| 遥控按键 `0x4E`、截图、WiFi 直传状态、时间同步 `0x4D` | Ark 专属通道 |
| 串口烧录、USB / Dock 连接、串口日志 | 依赖 Web Serial / USB，小程序无对应能力 |
| 动画工坊 | ForFilm 中写死 720×480 且要求 `FRAMEFILMARK`，对经典机型本就不开放 |
| 模板中心其余四个模板（签到/天气/倒计时/备忘录） | 产品决定只保留日历 |

## 3. 页面与信息架构

底部四栏对齐 ForFilm：**蓝牙 / Frame / Film / 设置**。设备文件管理收进设置页，不单独占 tab。

```
tabBar
├── 蓝牙        pages/shell/tabs/connect
├── Frame       pages/shell/tabs/create     （工具入口卡片）
├── Film        render/pages/film           （分包页面，页内共享底栏）
└── 设置        pages/shell/tabs/settings   （含 FILM 设置与设备文件）

Frame 详情页（底栏保留，当前 tab 高亮 Frame）
├── pages/frame/index        拾光 / 定影：快速转换、预览、发送
├── pages/quote/index        一言：随机 / 自定义、预览、发送
├── pages/batch/index        批量：多选、片单、前缀、逐张发送
└── pages/calendar/index     日历：月历、农历、节气、配色、发送
```

### 3.1 连接页 `pages/connect`

| 区块 | 内容 | 协议 |
|---|---|---|
| 设备列表 | 扫描结果（名称、信号、面板），过滤 `FRAMEFILM` 前缀 | BLE 扫描 |
| 连接状态 | 设备名、机型、屏幕、电量、当前显示文件、断开 | `0x42`、`0x23`、`0x08` |
| 网络与心跳 | WiFi 开关、SSID、密码、API 地址、连接/断开/清除、心跳地址与间隔 | `0x30`~`0x3B`、`0x3E`~`0x41` |
| 快速重连 | 缓存上次 `deviceId`，Android 可直接重连；iOS 需重新扫描 | — |

机型判定规则（必须遵守）：

- 广播名决定机型身份：`FRAMEFILM` 及其变体、`FRAMEFILMDOCK`；`FRAMEFILMARK` 属 Ark。
- `0x42` 只用于校正尺寸与像素排布，不得用面板 ID 反推机型。
- 能力按实际依赖判定：46/55 色 8bpp 仅 8bpp 设备可用；SZ 增强仅 Pro / Ark。

### 3.2 创作页 `pages/frame`

五张入口卡片，卡片样式沿用 ForFilm 的圆角卡片 + 图标 + 说明：

| 卡片 | 说明 | 详情页 |
|---|---|---|
| 拾光 | 相册选图，快速自适应转换 | `pages/frame` |
| 定影 | 系统相机拍照，快速转换 | `pages/frame` |
| 一言 | 随机 / 自定义文字排版 | `pages/quote` |
| 批量 | 多选队列、前缀、逐张发送 | `pages/batch` |
| 日历 | 月历 + 农历/节气/节日 + 配色 | `pages/calendar` |

### 3.3 日历页 `pages/calendar`

现有 `utils/tpl-calendar.js` 已做过微信适配，直接复用：

- 数据：`buildData(date)` 生成当月网格、农历、节气、节日、进度
- 渲染：`render(ctx, W, H, data, scheme)` 画到离屏画布
- 配色：沿用 `SCHEMES`，预览使用 1-bit 色板
- 后续：渲染结果统一进入 Film 编码管线，不再走旧 `template-sender`
- 依赖：`utils/tpl-calendar.js`（11.4KB）、`utils/template-core.js`（2.5KB）、`utils/e6pro.js`（26KB，模板分层转色）

### 3.4 Film 编辑器 `pages/film`

| 区块 | 内容 |
|---|---|
| 画布 | cover 适配、双指缩放、拖动、旋转 90°、重置 |
| 算法 | 按设备能力生成的算法列表（见第 6 节） |
| 参数 | 抖动强度、对比度、饱和度、明暗范围拟合、暖色收缩 |
| 预览 | 1-bit / 6 色预览，降采样绘制；参数变更防抖 |
| 输出 | 导出 `.film`、直接上传、文件名规则校验（ASCII ≤ 50 字符） |

### 3.5 设备文件（设置页内）

| 操作 | 协议 | 说明 |
|---|---|---|
| 刷新列表 | `0x06` | 分条返回文件 id + 名称 |
| 切换显示 | `0x07` + `0x08` | 切换后回读当前显示 |
| 删除 | `0x05` | 删除后刷新列表 |
| 当前显示 | `0x08` | 标记当前项 |

注意：ForFilm 设置页的文件管理走 Ark 的 `0x5B/0x60/0x61`，不能照搬；经典固件只有 `0x05/0x06/0x07/0x08`。

### 3.6 设置页 `pages/settings`

| 分组 | 项目 | 协议 |
|---|---|---|
| FILM 设置 | 文件多选、全选、删除所选、选择显示、照片切换模式（本地轮播 / 关闭 / WiFi 轮播） | `0x05`~`0x08`、`0x20`/`0x21` |
| 休眠 | 休眠开关、定时唤醒开关、间隔（10~2880 分钟） | `0x25`~`0x2A` |
| 设备 | 重启、恢复出厂、SD 格式化 | `0x24`、`0x22`、`0x2B` |
| 固件 | BLE OTA（选择文件、传输、进度、中止） | `0x10`~`0x13` |
| 调试日志 | BLE 收发日志、清空、复制 | — |
| 创作 | 默认算法（本地持久化） | — |
| 关于 | 小程序版本、协议版本、开源许可 | — |

OTA 在小程序中只能走 BLE：1~2MB 镜像预计 2~4 分钟，必须保持前台与屏幕常亮，中断即失败，不提供断点续传。

### 3.7 全局交互约束

- 同一时间只允许一台设备连接。
- 传输中禁止切页、断开、重复上传；退出页面前二次确认。
- 上传前校验：文件头、尺寸、像素排布、文件大小。
- 进度更新节流，禁止逐包 `setData`（见第 7 节）。

### 3.8 视觉还原边界

目标：静态版式、配色、卡片、图标、动效与 ForFilm 经典版一致；原生控件只能做到"外观一致、操作走系统"。跨 iOS / Android 不存在逐像素一致——字体度量、1px 边框、安全区本身就不同。

#### 可完全还原

| 项 | 做法 |
|---|---|
| 版式、间距、圆角、描边、阴影 | CSS 直接转 WXSS；尺寸用 px，不用 rpx，避免缩放漂移 |
| 配色 | 把 `style.css` 的 CSS 变量固化为常量，不再需要主题切换 |
| 卡片、按钮、标签、状态色 | 直接还原 |
| 动效 | `transition` / `@keyframes` 支持，缓动参数沿用原值 |
| 页面头部与底部导航 | `navigationStyle: custom` + 自绘导航，高度按安全区计算 |
| 图标 | 30 个内联 SVG 转图标字体，颜色随文字色 |
| 画布预览 | Canvas 2D 行为一致，按 dpr 缩放 |

#### 只能近似

| 控件 | ForFilm 做法 | 小程序限制 | 方案 |
|---|---|---|---|
| 滑杆 ×11 | 原生 `input[type=range]` + 自定义轨道/滑块 | 无 range；`<slider>` 只能改颜色与块大小 | 自绘 `ff-slider`（见 4.3.2） |
| 下拉 ×13 | 原生 `<select>`，样式完全可控 | `<picker>` 弹层是系统 UI | 自绘 `ff-select`（见 4.3.3） |
| 相机 | `<video>` + `getUserMedia` 内嵌取景 | `<camera>` 为原生组件，层级/圆角/滤镜受限 | 改用 `wx.chooseMedia` 系统相机 |
| 选文件 ×9 | `<input type=file>` | `wx.chooseMedia` / `wx.chooseMessageFile` | 按钮外观可一致，选择器是系统的 |
| 输入框 | `<input>` / `<textarea>` 完全可控 | 原生组件，光标、选中、placeholder 有平台差异 | 外观接近，细节不完全一致 |
| 字体 | Fredoka / Baloo / Noto Sans SC | 网络字体受域名白名单与体积限制 | 拉丁子集化嵌入；中文回退系统字体 |
| 页面转场 | 单页 + 隐藏切页，无转场 | `navigateTo` 默认带滑动动画 | 单页壳 + 组件切换（见 4.3.1） |

#### CSS 兼容改写

ForFilm 使用了若干小程序老内核不支持的特性，直接搬会破版：

| 特性 | 用量 | 处理 |
|---|---|---|
| `:has()` | 3 处 | 不支持，改为显式类名 |
| `color-mix()` | 5 处 | 不支持，预计算颜色值 |
| `clamp()` / `aspect-ratio` | 各 3 处 | 旧 Android 不稳，改固定值或 padding 技巧 |
| `gap` | 58 处 | 旧内核 flex gap 可能失效，加 margin 兜底 |
| `:is()` | 若干 | 拆分选择器 |
| `display: grid` | 9 处 | 可保留，关键布局改用 flex |
| `position: sticky` | 2 处 | 原生组件会盖住，需真机验证 |

结论：

- 静态视觉还原度约 95% 以上，可做到"一眼是同一个产品"。
- 滑杆、下拉、相机、文件选择、输入框 5 类只能外观一致，操作是系统行为。
- 只有画布区域与静态卡片可能做到截图级一致，整页逐像素对比不现实。

## 4. 技术选型

**使用微信原生小程序（WXML/WXSS + ES6 CommonJS），不引入 Taro / uni-app。**

理由：

1. ForFilm 本身是原生 JS/CSS，转成组件框架只增加运行时与构建层，无法带来代码复用。
2. 多端框架的运行时（百 KB 级）会挤占主包预算，而本项目已有 1.4MB LUT。
3. 本项目性能瓶颈在像素运算与 BLE 传输，不在 UI 更新；框架只会让更新链路更长。
4. 目标端只有微信，多端红利为零。

### 4.1 分层

```
core/        纯逻辑，可在 Node 下跑测试
  spec/        命令常量、面板表、能力矩阵（单一来源）
  film/        文件头、4bpp/8bpp 编码、像素排布
  render/      前置处理、算法注册表、各算法实现
  template/    日历等模板的数据与绘制
platform/    微信适配层
  ble/         连接、分包、队列、通知分发
  file/        选图、临时文件、导出
  canvas/      节点查询、离屏画布、1-bit 预览
  worker/      重算法线程
pages/       页面与组件（仅视图与交互）
components/  单页壳、底部导航、ff-slider、ff-select、设备状态条、传输面板、算法选择器、预览画布、提示与弹窗
```

约束：

- `core/` 不出现 `wx.*`、`document.*`。
- 页面不改写像素数据，只调用 `core` + `platform` 暴露的接口。
- 像素数组只在逻辑层与 Worker 内流转，不进入 `setData`。

### 4.2 分包与体积预算

| 包 | 内容 | 预算 |
|---|---|---|
| 主包 | 连接、Frame、片单、设置、Film 页面、`core` 基础、`platform` | ≤ 1.2MB |
| `render` 分包 | Atkinson 增强 LUT、SZ 增强、8bpp 调色板、四色算法 | ≤ 1.8MB |
| `template` 分包 | 日历（以及后续模板扩展） | ≤ 100KB |

LUT 优化：当前为 1.4MB base64。改为二进制资源（约 1.05MB）并用 `wx.getFileSystemManager().readFileSync` 读取，可省约 350KB；base64 作为兜底。

### 4.3 UI 基础组件

ForFilm 的 11 个滑杆、13 个下拉与内嵌相机是视觉还原的关键路径，统一做成自绘组件，不直接使用系统控件。

#### 4.3.1 单页壳与底部导航

ForFilm 是单页应用 + 隐藏切页，切 tab 没有转场。小程序若用 `navigateTo` 会带系统滑动动画，无法对齐，因此：

- 宿主页 `pages/shell` 承载四个 tab，用组件切换；非活动 tab 用 `hidden` 保活，保留滚动位置与画布状态。
- 不使用原生 `tabBar`，底部导航页内自绘，选中态、图标、圆角、间距按 `style.css` 还原。
- 子页面（Film、日历、批量）用覆盖层或二级页；需要返回手势时使用 `navigateBack`。
- 每个 tab 独立 `scroll-view`，记录 `scroll-top`。
- 代价：自绘导航会脱离系统返回手势。若更看重系统手势，可退化为原生页面切换，但会引入滑动转场。

#### 4.3.2 自绘滑杆 `components/ff-slider`

| 项 | 设计 |
|---|---|
| 属性 | `value`、`min`、`max`、`step`、`disabled`、`showValue`、颜色覆写 |
| 事件 | `changing`（拖动中，节流 16ms）、`change`（抬手） |
| 结构 | 轨道 view + 填充 view + 滑块 view + 数值气泡 |
| 取值 | 按轨道实际宽度换算比例，按 `step` 四舍五入，首尾吸附 |
| 性能 | 只改 `width` 与 `transform`，不重建节点；拖动中不触发重算法，抬手后才计算 |
| 无障碍 | `aria-role="slider"`、`aria-valuenow`、`aria-valuemin/max` |
| 外观 | 轨道 2.5px 描边、圆角 999px、滑块阴影与按压缩放沿用原 CSS |

参数显隐规则由算法注册表驱动（AE/自适应/SZ 隐藏强度滑块），与 ForFilm 一致。

#### 4.3.3 自绘下拉 `components/ff-select`

| 项 | 设计 |
|---|---|
| 收起态 | 与 ForFilm 的 select 完全一致：高度、描边、圆角、右侧箭头旋转 |
| 展开面板 | 页根绝对定位，`z-index` 高于内容、低于模态；遮罩点击关闭 |
| 选项 | 支持禁用项（非 Pro 的 SZ、非 8bpp 的 ColorQual）、分组标题、当前项高亮 |
| 长列表 | `scroll-view` 限高，自动滚动到当前项 |
| 边界 | 贴近屏幕底部时向上展开，避让安全区 |
| 冲突 | 打开前先让 `textarea` / `camera` 失焦或隐藏，避免原生组件盖住面板 |

#### 4.3.4 图标字体

- 由 30 个内联 SVG symbol 生成图标字体；描边图标先转轮廓再入字体，保留 `currentColor` 着色能力。
- 尺寸由 `font-size` 控制，选中/禁用态只改颜色，不额外出图。
- 个别转换失败的图标保留 base64 SVG 作为兜底。

#### 4.3.5 字体

| 范围 | 方案 |
|---|---|
| 拉丁字母、数字 | Fredoka / Baloo 2 按实际用字子集化，base64 内嵌，单文件约 30~60KB |
| 中文 | 不嵌入 Noto Sans SC，使用系统字体栈 `PingFang SC` / `MiSans` / `sans-serif` |
| 数字读数（电量、进度） | 使用 Fredoka 子集，保证字宽与网页一致 |

#### 4.3.6 相机与文件

- 相机：不使用 `<camera>` 做内嵌取景，改用 `wx.chooseMedia({ sourceType: ['camera'] })`。取景框由系统提供，无法还原网页的内嵌预览。
- 图片：`wx.chooseMedia`；聊天文件：`wx.chooseMessageFile`。按钮外观自绘，选择器为系统界面。
- 文本输入：`textarea` 为原生组件，弹层/下拉打开前必须失焦并收起，避免层级覆盖。

#### 4.3.7 统一交互参数

- 按压位移与缩放沿用原值：`translateY(1px)`、`scale(.98)`。
- 动效时长 130~200ms，缓动沿用 `--ease-bounce` / `--ease-out`。
- 提示与弹窗全部自绘，不使用 `wx.showToast` / `wx.showModal`。

## 5. 通信层

| 项 | 取值 |
|---|---|
| 帧头 | `0x55` |
| 帧结构 | `0x55 CH LEN DATA... SUM`，SUM 为全字节和 `& 0xFF` |
| 控制分包 | 192 字节 |
| MTU | 连接后尝试 200 |
| 控制命令间隔 | 50 ms |
| 数据包间隔 | 2 ms |

实现要点：

1. 全局单条写队列，命令串行；传输期间只允许传输帧与状态查询。
2. 写成功不等于设备已保存，文件上传以设备回包为准。
3. 断连恢复：取消任务、清队列、还原页面状态，不自动重传。
4. 进度节流：每 1% 或 100ms 更新一次，不逐包 `setData`。
5. 文件名只允许 ASCII，长度 ≤ 50（含 `.film`），非法字符映射为稳定短名。

## 6. 渲染算法完整移植

### 6.1 管线

```
源图
 └─ 画布适配（cover / 缩放 / 拖动 / 旋转）
     └─ 色彩调整（对比度、饱和度）
         └─ 源图适配（明暗范围拟合 rangeFit、暖色收缩 warmChroma）
             └─ 量化/抖动（算法注册表）
                 └─ 预览解码（4bpp/8bpp → RGB）
                     └─ 打包（v1 4bpp / v2 8bpp，按像素排布重排）
                         └─ 32 字节文件头 + 主体
```

### 6.2 算法清单与现状

#### 四色屏（面板 `0x08`）

ForFilm 的规则是：四色模式下 6 色专用算法**统一回退到 Floyd-Steinberg**。按此对齐，不引入额外算法。

现有小程序的 `e4Photo/e4Portrait/e4Vintage/e4Text` 是额外的四色优化，不属于 ForFilm 对齐范围：默认关闭；若产品希望保留，单独作为增强项放入能力矩阵，不混入算法列表。

## 7. 性能设计

| 措施 | 说明 |
|---|---|
| 大数组不过桥 | ImageData / 像素数组只存在逻辑层与 Worker，`setData` 只传进度与状态 |
| Worker | AE / SZ / 8bpp / 自适应等重算法放 `wx.createWorker` |
| 预览降采样 | 编辑预览按目标尺寸的 1/2~1/4 计算，导出时才全尺寸 |

| 内存 | 单次只保留当前图与一份输出；批量队列逐张处理并释放 |
| 常亮 | 传输与 OTA 期间 `wx.setKeepScreenOn` |

## 10. 验收方法

1. **编码一致性**：固定 6 张输入图（渐变、人像、文字、纯色块、自然照、高饱和） × 各算法 × 3 种尺寸，在 ForFilm 网页导出 `.film`，移植后逐字节比对 SHA-256。
2. **传输**：STD / Pro / Max 各完成 10 次上传，记录成功率与耗时；中途取消与断连恢复无残留状态。
3. **渲染**：对比预览与设备实际显示，确认颜色映射与像素排布无旋转/错位。
4. **性能**：千元 Android 上编辑、预览、导出无长时间白屏；内存无持续增长。
5. **兼容**：iOS 微信扫描、连接、上传、OTA 全流程。

## 11. 风险与待确认

| 风险 | 影响 | 应对 |
|---|---|---|
| 8bpp 算法长期闲置 | 增加分包体积 | 代码完整保留，入口按能力位；若确定不做 8bpp 设备再移除 |
| 1.4MB LUT 加载慢 | 首次进 Film 页等待 | 二进制资源 + 预加载 + 加载态 |
| 低端机像素运算超时 | 预览卡顿 | Worker + 降采样 + 防抖 |
| BLE OTA 耗时长 | 中途失败率高 | 明确提示、保持前台、提供中止与重试 |
| iOS 后台挂起 | 传输中断 | 常亮 + 页面内提示，不承诺后台 |
| 日历农历表范围 | 2100 年后失效 | 沿用现有表，超范围时降级为公历 |
| 与网页像素级差异 | 验收不通过 | 以 golden `.film` 比对为准，逐算法修正 |
| 自绘控件与系统控件行为差异 | 手感与无障碍不一致 | 统一交互参数、真机对比，保留系统选择器兜底 |
| CSS 新特性在旧内核失效 | 旧 Android 破版 | 按 3.8 清单改写并覆盖旧机型回归 |

待确认：

1. 四色屏是否保留小程序现有的 `e4*` 增强算法，还是严格按 ForFilm 只回退 FS。
2. Dock 是否需要在小程序提供传图入口（仅 BLE）。
3. 批量上传的单次上限与队列策略（数量、总大小、失败是否跳过）。
4. 相机与文件选择是否接受系统界面（无法还原网页的内嵌取景框）。
5. 单页壳会脱离系统返回手势，是否接受；若否，改用原生页面切换并接受转场差异。
